## 1. 这张图在整篇研究中要解决什么问题

Fig. 2 不是一张“模型效果图”，也不是一张“哪些变量最重要”的图。它回答的是更靠前、也更容易受到审稿人质疑的问题：

> 用来描述论文创新性和发表时潜在学术影响力的维度与指标，究竟从哪里来；为什么这些数量不是研究者主观指定；哪些指标证据最强；以及后续建模应在什么固定、可追溯的候选集合中进行。

因此，它建立的是一条**测量证据链**，而不是一条预测性能链：

```text
英文文献证据
→ 作者实际使用的术语
→ 可复核的检索框架
→ 论文级指标提及
→ 规范指标家族
→ 指标之后归纳的候选维度
→ 固定硬门槛
→ 四套嵌套、结果盲的建模特征集合
```

这条顺序是 Fig. 2 最重要的科学主张。它避免了下面这种容易产生确认偏差的旧式路线：

```text
先凭经验规定若干“机制”或“维度”
→ 再为每个维度挑一些看起来合适的指标
→ 再根据模型效果决定留下哪些
```

本研究采用的是相反顺序：**先让文献中的指标出现，再从指标测量的对象归纳维度，最后用事先冻结的规则决定可进入哪些集合。**

## 2. 读图前必须区分的六类数量

图中数字很多，但它们不在同一个层级。把它们混为一谈，是理解 Fig. 2 最常见的错误。

| 符号/数字 | 它是什么 | 它回答的问题 | 不是什么 |
|---|---|---|---|
| `K = 42` | 非冗余**检索概念领域** | 去哪里、用哪类术语找文献？ | 42 个模型维度 |
| `Q = 336` | 非冗余**逻辑检索式** | 有多少个独立语义的检索单元？ | 336 个指标或 336 次任意搜索 |
| `P = 367` | OpenAlex **物理请求** | API 实际发出了多少条请求？ | 新的理论构念；长查询拆分不会增加 `Q` |
| `432` | 规范**指标家族** | 文献中实际测量过什么？ | 432 个互不相关的最终模型变量 |
| `M = 66` | **候选维度** | 432 个指标测量了哪些较高层构念？ | 预先规定的“66 个机制” |
| `F = 7`、`D = 1` | 严格集中的最终指标数、实质预测维度数 | 在最严格可复现、T0、数据可得条件下，留下什么？ | 7 个“最有效”指标或 4 个实质创新维度 |

还要区分 Panel D 中的 `7 / 4`：它表示**7 个严格指标覆盖 4 个操作性维度**。其中只有 1 个是实质预测维度；另外 3 个分别是机会变量或背景控制维度。因此：

```text
严格核心：7 indicators / 4 operational dimensions
其中：D = 1 substantive predictive dimension
```

数字由固定输入和规则自然产生，不是“每个维度配若干指标”或“凑成一个好看的数目”。

## 3. 整张图的一句话读法

从上到下、从左到右，Fig. 2 讲的是：

1. **Panel A**：如何从不预设领域的英文启动检索，得到一个被检索验证、反复复核的文献—指标证据池；
2. **Panel B**：432 个规范指标家族如何先按文献角色、再按测量构念、最后按门槛资格被分类；
3. **Panel C**：严格可复现集合为何很小——不是因为事后追求稀少，而是因为 14 个独立硬门槛共同限制；
4. **Panel D**：不要只保留“最严格的 7 个”或不加区分地使用全部 432 个，而应预先冻结四个证据强度不同、彼此嵌套的特征集合，供后续模型比较与敏感性分析使用。

换言之，Fig. 2 的结论不是“7 个指标足够预测影响力”，而是：

> 在不使用未来结果、不过度声称文献覆盖、且不让模型表现反向选择变量的前提下，研究建立了一套从严格审计核心到可扩展建模集合的、透明可追溯的测量体系。

## 4. 整体范围与不应越过的解释边界

Panel A 顶部的 `Scope lock: English · paper level · T0 only · outcome blind` 是整张图的四个固定边界。

| 图中文字 | 实际含义 | 直接后果 |
|---|---|---|
| `English` | 只纳入英文题名、摘要或全文的证据文献 | 结果可能存在语言与地域覆盖偏差；不能表述为“全球全部文献” |
| `paper level` | 只考虑可归属到单篇论文的特征 | 只研究机构、国家或研究者总体、却无法落到论文的研究不直接构成入选指标 |
| `T0 only` | 输入信息最晚在论文发表时可得 | 未来引文、未来扩散、未来颠覆性、未来注意力都不能作为特征 |
| `outcome blind` | 指标入选不参考后续模型预测效果、OOF 相关或目标变量 | 后续性能图可以评价固定集合，但不能倒过来修改集合成员 |

这些边界解释了为什么 Fig. 2 与后续预测/验证图必须分开：本图只决定“**测量什么、如何确定**”；后续图才回答“**这些固定集合在某个任务上表现如何**”。

## 5. Panel A：证据从何而来，以及谁在审查

### 5.1 Panel A 的核心作用

Panel A 是整张图的主脊柱。它证明维度和指标并不是从一个先验的“12 个领域”或“50 个指标”清单开始，而是通过：

```text
领域无关启动检索
→ 英文术语提取与标准化
→ 检索框架生成、PRESS 与种子召回验证
→ 正式检索、筛选、全文指标普查
→ 指标之后归纳候选维度
→ 固定硬门槛
```

Panel A 分为三层：最上方是 7 个正式阶段，中间是 12 轮发现迭代，底部是复核链和审计覆盖。

### 5.2 最上方的 7 个阶段点

中间横线和箭头表达的是**证据处理顺序**，不是各节点数值大小。圆点是阶段锚点；`01–07` 是固定的阅读顺序。

| 阶段 | 图中数字与文字 | 代表什么 | 正确解读 |
|---|---|---|---|
| `01 Domain start` | `bootstrap` | 以“论文对象 × 创新/质量/潜在影响 × 指标/验证证据类型”组成领域无关启动检索 | 起点不是团队、文本、参考文献或期刊等预设领域 |
| `02 Source terms` | `3,615 → 367` | 3,615 个来源可追溯的原始英文术语，经 H2 处置、规范化与同义/参数变体合并后形成 367 个术语家族 | 全链条实际还有 `3,615 raw → 3,170 H2 retained → 1,102 canonical → 367 families`；图中压缩显示首尾以保持可读性 |
| `03 Frozen search frame` | `42 / 336 / 367` | 42 个检索概念领域、336 个独立逻辑检索式、367 条 OpenAlex 物理请求 | 42 是检索导航分类；336 是语义检索式；367 是 API 拆分后的执行数，三者不能互换 |
| `04 Formal census` | `30,332 → 363` | 冻结检索框架后的正式发现池与引文追踪，最终进入指标普查的英文来源论文数 | 30,332 是正式查询的唯一记录量；它不是简单地直接减为 363。题名摘要终末处置记录为 9,515 条，其中 363 纳入、9,152 排除 |
| `05 Canonical indicators` | `1,685 → 432` | 1,685 次文献中的指标提及，经名称、同义词、变体和定义消歧后形成 432 个规范指标家族 | 一个“指标家族”可在多篇文章以不同名称、时间窗、标准化或编码形式出现；另有 13 条定向公式补全记录，但没有新增家族 |
| `06 Candidate dimensions` | `M = 66` | 从指标的被测构念、解释角色、信息来源、T0 边界和偏差风险出发，归纳出 66 个候选维度 | 维度在指标普查之后才出现，因此不是用来强行容纳指标的预设框架 |
| `07 Frozen hard gates` | `14 gates` | 在特征集合成员资格确定前冻结的 14 条可审计规则 | 门槛不是模型训练后的“表现筛选”；它们的详细通过数在 Panel C |

#### 这个阶段链最容易被误读的三个点

1. `42` 不等于 `66`：前者解决检索覆盖，后者解决模型构念分类。
2. `1,685` 不等于 `432`：前者是文献中的出现次数，后者是合并后的规范实体。
3. `30,332 → 363` 不是一个单一的 PRISMA 漏斗：中间存在去重、语言判断、终末筛选和引文追踪；所有 9,515 条终末处置仍在审计表中保留。

### 5.3 中部：12 轮发现迭代条带

`R1–R12` 每一组有两根小柱：

| 视觉元素 | 含义 |
|---|---|
| 蓝柱 | 该轮新增的非冗余英文术语数量 |
| 橙柱 | 该轮新增的规范指标家族数量 |
| 横向排序 | 发现与复核的时间顺序，不是按效果、质量或重要性排序 |
| `R12` 橙色虚线框 | 终止点的透明标记 |
| `R12: pragmatic stop; Δ 10 terms · Δ 9 families` | 第 12 轮仍有新增，终止理由是项目所有者登记的边际收益判断，而不是“双零饱和” |

这部分不能被表述成“第 12 轮已经没有新术语或新指标”。实际恰好相反：第 12 轮新增了 10 个术语家族与 9 个指标家族。图中特意保留橙色虚线，目的就是让读者看到这一方法学限制，而不是把停止包装成严格的统计饱和。

因此，正确表述是：

> 该检索采用证据饱和导向的、分轮迭代设计；第 12 轮因边际收益被登记为务实终止点。它支持较高的覆盖透明度，但不证明穷尽了世界上所有相关研究。

### 5.4 底部左侧：Review trail（审查链）

三个色块不是三类指标，而是三个**复核角色**：

| 角色 | 图中文字 | 具体审查对象 | 在流程中的权力 |
|---|---|---|---|
| `AI extraction` | `surface candidate terms and indicators with source evidence` | 初步抽取候选英文术语、指标、来源片段与上下文 | 提供候选；不能单独删除文献、建立正式维度或批准最终指标 |
| `H1 verification` | `independently check definitions, roles, and T0 boundary` | 独立核对定义、角色、论文级归属、发表时边界和来源证据 | 形成与初提取分离的复核判断 |
| `H2 adjudication` | `resolve disagreements on merge, split, and final decisions` | 处理分歧，决定术语/指标的合并或拆分、最终角色和处置 | 其仲裁标签成为冻结结果 |

这里的 `H1`、`H2` 是**审查角色标签**，不等同于“两个固定的真人审稿者”。证据记录中：

- 7 份早期自动草稿工作表已由项目所有者人工复核并确认采用，因此图中显示 `attested sheets = 7`；它们应被准确称为“人工确认采用的自动草稿”，而不是从零独立手工编写的表。
- 后续复核由独立 Codex 会话完成，而不是本机 Qwen 或同一提取会话自行批准；审计中记录 `119` 次独立 AI 复核运行。
- `50,314 reviewed rows` 是跨筛选、术语、指标与维度阶段的累计逐项审查记录，**不是 50,314 篇不同论文**，也不是 50,314 个独立指标。

### 5.5 底部右侧：审计覆盖账本

| 指标 | 图中值 | 说明 |
|---|---:|---|
| `attested sheets` | 7 | 已登记、哈希核对通过的人工确认采用工作表数 |
| `AI reviews` | 119 | 独立 Codex 复核运行数；不是 119 位人工评审者 |
| `reviewed rows` | 50,314 | 跨阶段累计复核行数；同一记录可在多个阶段出现 |
| `seed recall` | 62/62 | 62 篇可索引开发/隐藏种子均被冻结检索框架召回 |
| `PRESS issues` | 0 | 活跃检索式中没有未解决的 PRESS 审查问题 |

`62/62` 的意义不是“找到了全部世界文献”，而是已知的、可索引阳性种子没有漏召回。初始召回是 `51/62`；对 11 篇漏召回种子逐篇排查后，只把文献中可追溯的英文同义词加入检索框架，完成 10 项来源驱动修复，才得到 62/62。

### 5.6 Panel A 的颜色与图形语言

| 颜色/形状 | 表达的内容 | 不表达什么 |
|---|---|---|
| 深蓝主脊柱 | 冻结的证据顺序 | 数值大小或预测强度 |
| 蓝柱 | 新英文术语 | “更好的术语” |
| 橙柱与虚线 | 新指标家族及 R12 的务实终止披露 | 真正的双零饱和 |
| 蓝、绿、紫审查文字 | AI、H1、H2 的角色区分 | 证据质量的高低排序 |
| 右侧大数字 | 审计覆盖 | 独立论文或独立人员数量 |

## 6. Panel B：为什么“指标先于维度”

### 6.1 Panel B 的核心作用

Panel B 是一张守恒式 Alluvial（流带分类图）。每一条流带的宽度代表一组规范指标家族的数量，沿着三列移动：

```text
文献中被赋予的角色
→ 指标实际测量的构念家族
→ 根据固定门槛得到的集合资格层级
```

它要证明两件事：

1. **模型维度不是检索领域，也不是先验标签。**它们来自指标被测构念的独立编码；
2. **入选资格不是由“指标属于哪个维度”决定，而是由统一门槛决定。**同一构念的指标可以因证据、T0、全文公式或数据可得性不同，流向不同集合层级。

Panel B 中每一列标题的 `n = 432` 都指 432 个规范指标家族，不是 432 篇论文。

### 6.2 左列：Literature role（文献角色）

左列问的是：**原始文献把该指标放在什么证据角色中讨论？**

| 左列节点 | 家族数 | 含义 |
|---|---:|---|
| `Direct innovation` | 31 | 文献直接作为创新性、创新内容或新颖性相关测量讨论 |
| `T0 substantive` | 258 | 文献将其作为发表时可观察的实质潜力、质量或潜在影响相关特征讨论 |
| `T0 opportunity` | 105 | 文献将其视为可影响机会、可见性、协作或扩散条件的发表时变量 |
| `Context control` | 38 | 文献中更适合作为背景控制或规范化上下文，而非实质创新机制 |

左列的彩色窄条高度与数字成比例。它不表示模型中的因果路径，也不表示该角色一定会获得更高预测性能。

### 6.3 中列：Coded construct family（编码后的构念家族）

中列回答：**这些指标究竟在测量哪类构念？**这是从指标归纳维度的层级，而不是旧图中容易引起误解的 `model role`。

| 中列节点 | 家族数 / 候选维度数 | 含义 |
|---|---:|---|
| `Innovation content` | 27 families · 6 dim | 直接描述创新内容、知识重组或新颖性性质的构念 |
| `T0 impact potential` | 197 · 29 | 发表时能够描述潜在影响、质量、可见性条件或实质潜力的构念 |
| `Opportunity context` | 115 · 15 | 协作、机会、扩散环境等情境构念 |
| `Background controls` | 38 · 10 | 作者、发表、领域等需要控制或规范化的上下文构念 |
| `Sensitivity-only` | 51 · 6 | 允许在宽松敏感性集合中探索，但不应被当作核心实质预测机制的构念 |
| 未标注浅灰小节点 | 4 · 0 | 4 个家族在维度归纳前已被排除，未获得正式候选维度；为避免标签拥挤，图上不写出文字 |

前五个标注节点合计为 428；加上 4 个未分配家族后才是标题中的 432。这个差异是有意保留的审计信息，不是图形或数据丢失。

中列中的 `27 families · 6 dim` 必须读成“27 个指标家族归属于 6 个候选维度”，不能读成“27 个维度”。

### 6.4 右列：Gate-defined tier（由门槛定义的资格层）

右列把 432 个家族分成五个**互斥**层；括号内 `cum.` 是把严格层逐层累加后的嵌套集合大小。

| 右列节点 | 独占家族数 | 累积集合大小 | 含义 |
|---|---:|---:|---|
| `Strict` | 7 | 7 | 通过 14 条硬门槛的严格核心 |
| `Full text` | 9 | 16 | 不在严格 7 中、但进入英文全文/公式证据集合的增量 |
| `Source` | 138 | 154 | 不在前两层中、但有原始/基础来源证据且满足 T0 安全基线的增量 |
| `Broad T0` | 67 | 221 | 不在前面层中、但满足宽松 T0 安全基线的增量 |
| `Excluded` | 211 | 432 | 未进入宽松 T0 集合的其余家族 |

所以 `Full text · 9 (cum. 16)` 不是说全文集只有 9 个指标；它表示全文集在严格 7 之外再增加 9 个，因此总数为 16。

### 6.5 如何阅读一条流带

选择任意一个左侧节点，顺着同色或浅色流带到中间，再顺着中间流带到右侧：

```text
某文献角色中的若干指标
→ 被编码为某类构念
→ 其中一部分进入 Strict / Full text / Source / Broad T0 / Excluded
```

流带颜色以**中间构念角色**为主：蓝色偏向创新内容，绿色偏向 T0 潜力，金色偏向机会，灰色偏向背景或极小流，紫色偏向敏感性构念。小于 10 个家族的细流会转为浅灰，以降低交叉噪声；这并不表示它们“无效”。

节点色的含义则不同：左列按文献角色着色，中列按构念角色着色，右列按资格层级着色。颜色是分类辅助编码，真正的数量读数由节点高度、流带宽度和标签数字共同承担。

### 6.6 Panel B 不在表达什么

本图没有 Spearman 相关、网络边、因果效应、变量重要性或模型性能。流带粗不代表预测更强，某个构念流入严格层多也不代表它是“最重要机制”。它只是一个**可守恒的分类账本**：左、中、右三列各自总数都为 432。

## 7. Panel C：14 条硬门槛为何不是“漏斗图”

### 7.1 Panel C 的作用

Panel C 将 432 个规范指标家族逐一接受 14 条固定检查。每一行的线长和右侧数字是：

```text
通过该单条门槛的家族数 / 432
```

它展示的是**边际通过数**，不是按行顺序逐步淘汰的样本数。因此 Panel C 不能读成“432 → 432 → 221 → … → 7”的漏斗。

同一个指标可以同时失败多个门槛；不同门槛的通过集合也会部分重叠。最终严格集的 7 个指标来自 14 个通过集合的**交集**。

### 7.2 每一行的含义与数量

图中 `Gxx` 是稳定的审计 ID，不是质量排名，也不是执行先后顺序。显示顺序按规则组组织：范围/时间边界 → 偏差与结果隔离 → 来源与公式 → 实现质量 → 独立审查。

| 组别 | 图中行 | 通过数 | 这条门槛检查什么 |
|---|---|---:|---|
| 范围与时间 | `G02 Paper level` | 432 | 是否确实可以在论文级计算，而不是只描述作者、机构或国家总体 |
| 范围与时间 | `G01 Allowed role scope` | 432 | 是否属于创新、T0 潜力、机会变量或允许的背景控制范围 |
| 范围与时间 | `G05 T0 computable` | 221 | 最晚能否在发表时获得或稳定推导 |
| 范围与时间 | `G06 No future information` | 432 | 不得使用未来引文、未来扩散、未来颠覆性或未来注意力 |
| 偏差/结果隔离 | `G08 Bias guardrail` | 432 | 不违反保护属性与偏差防护规则 |
| 偏差/结果隔离 | `G09 No fatal validity issue` | 432 | 不存在致命构念效度问题 |
| 偏差/结果隔离 | `G10 Outcome blind` | 432 | 入选没有参考目标、OOF 或预测效果反馈 |
| 来源/公式 | `G03 Foundational evidence` | 167 | 有同行评议的原始应用或基础数学来源 |
| 来源/公式 | `G13 Full-text/formula evidence` | 16 | 已核验英文关键全文与公式证据 |
| 实现/质量 | `G04 Reproducible definition` | 7 | 公式、参数、方向和缺失处理可复现 |
| 实现/质量 | `G07 Local data ready` | 12 | 当前 T0 数据已具备，或能从审计输入稳定推导 |
| 实现/质量 | `G11 Quality audit` | 12 | 通过实现层的数据质量检查 |
| 实现/质量 | `G12 Nonconstant` | 12 | 在有效分析样本中不是常量 |
| 独立审查 | `G14 H2 approval` | 16 | 经角色分离的 H2 独立批准 |

### 7.3 颜色、点和横线如何读

| 视觉元素 | 含义 |
|---|---|
| 左侧短色线 | 门槛所属规则组：青绿为范围/时间，紫色为偏差或实现质量，深蓝为来源/公式，橙色为独立 H2 审批 |
| 浅灰全长线 | 432 个家族的共同分母 |
| 彩色线段 | 通过该条门槛的比例 |
| 空心圆点 | 该门槛通过比例的终点 |
| 最右数字 | 通过数的精确值 |

`G03 = 167` 不等于 Source 集有 167 个指标，因为 Source 集还要求 T0 安全和其他基线规则，最终交集是 154。类似地，`G13 = 16` 不自动表示这 16 个都通过 14 门槛；严格集仍须同时满足所有其他条件。

### 7.4 为什么最后是 7，而不是“按效果挑出 7”

Panel C 显示真正的瓶颈集中在证据完整度与可操作性，而不是在范围定义：

- 432 个家族都满足论文级、允许角色、无未来信息、偏差防护和结果盲的基础定义；
- 只有 221 个明确满足 T0 可计算；
- 只有 167 个具备原始/基础来源证据；
- 只有 16 个完成英文关键全文/公式核验；
- 只有 7 个具有完整可复现定义；
- 12 个可从本地 T0 数据稳定实现、通过质量检查且不是常量；
- 16 个完成 H2 独立批准；
- 最终严格集合是这些条件的交集，得到 7。

这不表示其余 425 个指标“没有学术价值”，也不表示 7 个指标一定预测最好；它仅表示在当前冻结的、最强可复现性与本地可计算性要求下，只有 7 个适合进入严格确认性核心。

## 8. Panel D：四套应如何用于后续建模的嵌套特征集合

### 8.1 Panel D 的核心作用

Panel D 将 Panel C 的单条门槛审计转化为四套事先冻结的、彼此嵌套的操作性集合：

```text
7  ⊂  16  ⊂  154  ⊂  221
```

四个框现在有相同的左右边界，框的物理宽度**不编码数量**；这一设计避免读者把框长误读成指标数。数量由每行中央的 `指标数 / 维度数` 与右侧组成条表达。

### 8.2 四个集合的具体定义

| 图中行 | 指标 / 维度 | 资格规则 | 在后续实验中的定位 |
|---|---:|---|---|
| `Strict core` | `7 / 4` | 同时通过全部 14 条硬门槛 | 最严格、最可解释的确认性基线 |
| `Full-text set` | `16 / 10` | T0 安全基线 + 原始/基础来源 + 英文全文/公式证据 | 高证据强度的中间扩展集 |
| `Primary scalable set` | `154 / 48` | T0 安全基线 + 原始/基础来源 | 推荐的主建模集合；兼顾来源基础与规模 |
| `Broad T0 set` | `221 / 55` | 仅保留 T0 安全基线 | 敏感性分析的宽松上界，不应替代主结论 |

它们的成员关系必须保持：

```text
Strict core ⊆ Full-text set ⊆ Primary scalable set ⊆ Broad T0 set
```

所以第二行的 16 不等于“另加 16 个”，而是包含了严格 7；154 和 221 同理。

### 8.3 右侧小型组成条：F、L、S、X 是什么

每个集合的右侧条表示该集合内部的**操作化层级**，而不是理论维度、数据效果或模型重要性。

| 缩写 | 全称 | 图形样式 | 含义 |
|---|---|---|---|
| `F` | Source formula | 深蓝实色 | 可按英文来源中已核验的公式/定义直接实现的指标 |
| `L` | Local formula surrogate | 中蓝实色 | 使用本地可获得、来源可追溯的组成部分构成的透明替代公式；它不是声称逐字复刻原始公式 |
| `S` | Structured construct proxy | 浅蓝实色 | 使用出版、作者、参考文献、结构化元数据等 T0 输入近似同一构念；有明确映射，但不是同一公式 |
| `X` | Title/taxonomy lexical proxy | 最浅蓝斜线 | 用标题、分类或词汇相似度等代理表达构念；可扩展但与原始公式距离最远 |

各集合的组成如下：

| 集合 | 组成条文字 | 含义 |
|---|---|---|
| Strict 7 | `F7` | 7 个均为已核验来源公式/定义 |
| Full-text 16 | `F12 L4` | 在 12 个直接公式之外，有 4 个透明本地公式替代 |
| Primary scalable 154 | `F12 L4 S79 X59` | 12 个直接公式、4 个本地替代、79 个结构化构念代理、59 个词汇/分类代理 |
| Broad T0 221 | `F12 L4 S90 X115` | 在 Primary 集基础上进一步增加结构化与词汇代理，用于宽松敏感性分析 |

因此，`154` 的正确含义是：

> 154 个来源驱动、T0 安全且可操作化的指标，不是 154 次原始文献公式的逐字复制。

这也解释了为什么 Panel D 同时保留“来源证据层级”和“本地操作化层级”：前者说明概念从哪里来，后者说明在现有数据中怎样实现，两者不能混为一谈。

### 8.4 严格 7 个指标究竟覆盖哪 4 个维度

严格集的 7 个指标是：

| 操作性维度 | 角色 | 严格指标 |
|---|---|---|
| Knowledge diversity and integration potential | `t0_potential`，唯一实质预测维度 | Reference balance；Reference variety |
| Collaboration breadth and type | `opportunity` | International collaboration；Country count（图中对 `International collaboration scale` 的显示别名） |
| Author team composition context | `context_control` | Author count |
| Publication and venue context | `context_control` | Journal identity；Publication year |

这就是 `7 / 4` 与 `D = 1` 可以同时成立的原因：四个操作性维度中，只有“知识多样性与整合潜力”被计为严格的实质预测维度；协作是机会变量，团队与发表信息是控制变量。后续文字中不能把“4 个严格维度”写成“4 个创新机制”。

### 8.5 Panel D 的边框和背景

| 行样式 | 含义 |
|---|---|
| `Strict core`：深色实线、白底 | 最严格审计核心 |
| `Full-text set`：细浅灰实线、白底 | 证据强度很高但放宽本地实施等条件的扩展 |
| `Primary scalable set`：深蓝边框、浅蓝底 | 主建模集合；视觉上是 Panel D 的重点 |
| `Broad T0 set`：灰色虚线、浅灰底 | 敏感性上界；强调其宽松性质，而不是主要确认性结果 |

边框样式是证据层级标记，不是模型得分标记。

## 9. 四个 Panel 如何共同构成一条可审稿的论证

| Panel | 回答的审稿问题 | 不能替代的其他 Panel |
|---|---|---|
| A | “为什么是这些搜索领域、检索式、文献与候选指标？” | 不能告诉读者哪些指标最终可计算 |
| B | “文献中的指标如何被转为维度，而不是先规定维度？” | 不能证明任何单条指标满足严格可复现要求 |
| C | “为什么严格集只剩 7 个？筛选是不是随意？” | 不能展示建模时有哪些可扩展但较宽松的集合 |
| D | “后续模型到底用哪一套特征，强弱证据如何区分？” | 不能显示预测好坏或因果机制 |

读者理想的阅读顺序是：

```text
A：证据来源与过程可信
→ B：指标先于维度，分类守恒
→ C：统一门槛解释严格筛选
→ D：固定集合支持后续比较
```

其中最关键的逻辑关系是：

```text
Panel A 产生文献和指标
Panel B 归纳并映射指标与维度
Panel C 对全部指标施加固定规则
Panel D 把规则交集冻结为后续实验集合
```

任何后续模型结果都只能附着在 Panel D 已冻结的集合上，不能回头改变 A、B 或 C 的成员资格。

## 10. 后续实验应如何延续 Fig. 2 的思路

### 10.1 建模前：把 Fig. 2 当作“变量注册表”

在开始训练模型、计算 OOF Spearman、做消融或做时间外验证前，应固定以下内容：

1. 使用哪一个集合：`Strict 7`、`Full-text 16`、`Primary 154` 或 `Broad T0 221`；
2. 每个指标的规范 ID、所属维度、角色和操作化层级；
3. 指标的最大信息时间必须仍是 `T0`；
4. 缺失处理、代理计算、标准化、变换和数据质量规则；
5. 训练/验证划分、目标定义和性能指标。

第 1–4 项属于 Fig. 2 的测量注册；第 5 项属于后续模型实验。两者必须在记录和图表中分开。

### 10.2 推荐的四套集合使用方式

| 集合 | 推荐用途 | 解释时应强调什么 | 不应声称什么 |
|---|---|---|---|
| Strict 7 | 确认性、可解释基线；检查最强证据下结论是否成立 | 定义、公式、T0 和数据可得性最严格 | 它天然是预测最优集合 |
| Full-text 16 | 高证据强度的稳健扩展 | 仍有英文关键全文/公式证据 | 与 Strict 的差异必然来自“更多机制” |
| Primary 154 | 主训练与主要比较集合 | 可扩展、来源驱动、T0 安全；需披露 F/L/S/X 组成 | 154 个都是原始公式复刻 |
| Broad T0 221 | 敏感性上界；测试结论对更宽操作化是否稳健 | 只满足基础 T0 安全，不代表证据同等强 | 它是主确认性分析或等价于 Primary |

最干净的后续比较是：在**相同数据、相同时间切分、相同目标、相同训练协议和相同评价函数**下，仅替换这四个冻结特征集合。这样任何性能差异才能被解释为“测量证据层级/操作化范围不同”带来的经验差异，而不是换了数据或实验方案。

### 10.3 推荐的报告顺序

后续结果图或表可以采用：

```text
严格 7：确认性基线
→ 全文 16：高来源证据扩展
→ 主集合 154：可扩展主分析
→ 宽松 221：敏感性边界
```

每次报告都同时给出：

- 指标数与维度数；
- F/L/S/X 操作化组成；
- 预测变量、机会变量和背景控制变量的角色构成；
- T0 边界；
- 相同的评价协议；
- 不确定性区间或重复切分结果。

模型内的重要性、SHAP、系数或 OOF 相关应被称为**固定集合内的事后分析**，不能被重新用作 Fig. 2 中指标或维度是否存在的证据。

### 10.4 如果以后要新增指标或维度

不要把新指标直接追加到 154 或 221 中。正确做法是创建一个新的、显式版本的证据框架，例如 `evidence_derived_v4`：

```text
新增英文证据
→ 记录原始术语与来源
→ 独立编码和 H2 仲裁
→ 检查是否新增非冗余检索领域/逻辑检索式
→ 提取与去重指标
→ 指标后归纳候选维度
→ 同一套门槛或明确版本化的新门槛
→ 新集合、新哈希、新图或补充表
```

旧版 `v3` 的 `7 / 16 / 154 / 221` 必须保持可重现，不能因新增证据而静默改变。这样才能区分“原结论是否稳健”与“知识库是否扩展”。

## 11. Fig. 2 支持什么结论，以及不支持什么结论

### 可以支持的结论

- 检索领域、逻辑检索式、候选指标和候选维度不是预先按配额指定；
- 检索框架经过英文术语来源、PRESS 和开发/隐藏种子召回验证；
- 432 个指标家族在维度归纳前完成了名称与变体消歧；
- 候选维度在指标之后形成；
- 严格集、全文集、主集合和敏感性集有清晰、嵌套、结果盲的成员规则；
- 严格 7 个指标的少量结果来自门槛交集，而不是模型效果导向的挑选；
- 154 个主集合指标在来源证据与本地操作化之间有显式层级披露。

### 不可以支持的结论

- “已经穷尽世界上所有有关论文创新性的文献”；
- “英文文献代表所有语言、地区和学科传统”；
- “严格 7 指标一定比 154 或 221 指标预测得更好”；
- “流带宽度、节点颜色或门槛通过数证明因果机制”；
- “所有 154 个指标都是原始公式的直接复现”；
- “H1/H2 是两位固定的真人编码者”；
- “第 12 轮达到双零饱和”。
