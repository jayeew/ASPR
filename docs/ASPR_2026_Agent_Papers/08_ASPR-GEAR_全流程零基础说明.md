# ASPR-GEAR 全流程零基础说明

## 1. 这套系统到底要做什么

这套系统的目标很简单：

> 输入一篇待审论文，输出一份有证据、能追溯、不会乱下结论的同行评审报告。

普通的大模型审稿往往是：

```text
论文 → 大模型 → 审稿报告
```

这种方法的问题是，大模型可能写得很像专家，但它说的内容未必有证据。

ASPR-GEAR 不允许大模型直接完成全部工作。它采用：

```text
论文
→ 拆解论文
→ 建立检查清单
→ 建立评审工作台账
→ 分别检查论文内部、外部文献和图谱信号
→ 验证每条评审意见
→ 只保留验证通过的意见
→ 生成最终评审报告
```

`ASPR-GEAR` 是系统名称。可以将它理解为“由图谱校准和证据控制驱动的 ASPR 同行评审系统”。

这套系统最重要的原则不是“让更多智能体讨论”，而是：

> 每一条重要评审意见都必须回答：它根据什么证据得出？证据在哪里？证据是否早于审稿时间？证据是否真的支持这句话？

---

## 2. 先用一个生活例子理解整个架构

可以把系统想象成一家医院正在给一位病人会诊。

| 系统组成 | 医院中的对应角色 | 实际职责 |
|---|---|---|
| 论文编译器 | 负责整理病历的工作人员 | 把论文拆成带编号的段落、主张、方法和结果 |
| 论文专属检查表 | 针对病人的检查项目 | 决定这篇论文应该重点检查什么 |
| 评审状态 | 统一电子病历 | 记录已经查了什么、还缺什么、哪些结论可靠 |
| 证据主管 | 会诊主任 | 决定下一步该调用哪个检查工具 |
| 内部评审器 | 负责检查病人本身的医生 | 检查论文的方法、实验、结果和表述 |
| 外部证据检索 | 查阅医学文献 | 寻找相关工作和真正的先行研究 |
| 图谱先验 | 风险预测仪器 | 提醒哪些地方值得重点检查，但不能直接下诊断 |
| 证据验证器 | 检验科和质控人员 | 检查每条结论是否真的有证据 |
| 过程诊断 | 会诊完整性检查 | 告诉我们这次检查是否充分，哪里仍然有限 |
| 评审编译器 | 整理最终诊断书的人 | 只把验证通过的意见写进最终报告 |

这个比喻中最重要的一点是：

> 图谱只是检查仪器，不能代替医生下诊断；大模型只是参与检查的医生，也不能绕过证据和质控直接签发最终报告。

## 3. 系统的十个主要模块

下面先只讲“有哪些主要模块”，暂时不讲代码。

### 模块一：论文输入

正式运行时，输入包括：

- 论文的 PDF 文件；
- 或者论文的 Markdown 文本；
- 论文标题；
- DOI；
- 投稿日期或审稿日期；
- 期刊、会议和学科信息。

`PDF` 是便携式文档格式，也就是常见的论文文件。

`Markdown` 是一种简单的纯文本排版格式，文件通常以 `.md` 结尾。

`DOI` 是数字对象唯一标识符，可以理解为论文在互联网上的永久身份证号码。

本次开发测试有一点不同：原始论文已经被处理成结构化文件，所以直接读取冻结的论文结构，不重新解析 PDF。

---

### 模块二：论文编译器

论文编译器的英文名称是 `Paper Compiler`。

- `Paper`：论文；
- `Compiler`：编译器，也就是把一种原始材料转换成机器可处理结构的程序。

它负责把论文转换成 `PaperIR`。

`IR` 是 `Intermediate Representation` 的缩写，中文是“中间表示”。所以 `PaperIR` 就是“论文的机器可读中间表示”。

论文编译器会生成：

1. 论文身份；
2. 每一页的文本；
3. 每个章节；
4. 带固定编号的证据段落；
5. 作者提出的主要主张；
6. 方法与结果清单；
7. 参考文献清单。

例如论文里有一句：

> 我们首次提出一种图谱校准的自动审稿方法。

系统可能将其保存为：

```text
主张编号：C-001
主张类型：创新性主张
主张强度：强
证据段落：P:S-abc123
```

这里：

- `C` 来自 `Claim`，意思是“主张”；
- `P` 来自 `Paper`，意思是“目标论文”；
- `S` 来自 `Span`，意思是“一段具有固定位置的文本”；
- `P:S-abc123` 就是目标论文中某个段落的证据编号。

后面的模块不应该随便说“论文中提到过”，而应该引用具体的 `P:S-*` 编号。

---

### 模块三：论文专属检查表

论文专属检查表的英文名称是 `Paper-specific Rubric`。

- `Paper-specific`：针对这篇具体论文的；
- `Rubric`：评分或检查标准。

它的作用是回答：

> 对这篇具体论文，我们应该检查哪些问题？

它不是给所有论文使用同一张空泛表格。

例如，机器学习论文可能需要检查：

- 是否比较了合理的基线方法；
- 是否报告了多次随机实验；
- 是否有消融实验；
- 是否存在训练数据泄漏；
- 表格数字是否支持结论。

医学论文可能需要检查：

- 样本量是否足够；
- 是否设置对照组；
- 是否随机分组；
- 是否报告置信区间；
- 是否把相关关系写成因果关系。

第一版检查表由确定性程序生成，不调用大模型，也不读取人工审稿意见。这样做是为了避免“用答案生成考题，再拿同一个答案参加考试”。

---

### 模块四：评审状态

评审状态的英文名称是 `Review State`。

- `Review`：评审或审稿；
- `State`：当前状态。

它是整个系统最重要的统一工作台账。

它会记录：

- 论文有哪些主要主张；
- 哪些主张是“首次”或“突破性”等强主张；
- 当前有哪些内部评审意见；
- 哪些意见已经找到论文内部证据；
- 哪些意见需要查外部文献；
- 找到了哪些候选文献；
- 候选文献和目标论文是什么关系；
- 是否做过反事实检索；
- 是否做过稳定性测试；
- 哪些意见已验证；
- 哪些意见仍未解决；
- 已经使用了多少检索预算；
- 为什么停止继续检索。

系统一开始建立的是“空评审状态”。这时只有论文、检查表和时间边界，还没有评审意见和外部证据。

这样设计是为了保证：

> 所有评审活动都在统一状态中发生，而不是先让模型写完一篇报告，再倒过来寻找证据。

---

### 模块五：证据主管

证据主管的英文名称是 `Evidence Supervisor`。

- `Evidence`：证据；
- `Supervisor`：主管或监督者。

它是整个系统中唯一负责调度的智能体。

这里的 `Agent` 中文是“智能体”，指可以根据当前情况决定下一步动作的程序。

证据主管不负责亲自写最终报告。它只负责回答：

> 根据当前评审状态，下一步最应该做什么？

它只能从有限动作中选择：

| 动作名称 | 中文解释 |
|---|---|
| `GRAPH_CALIBRATE` | 运行图谱校准 |
| `RUN_INTERNAL_REVIEW` | 运行论文内部评审 |
| `VALIDATE_INTERNAL` | 验证内部评审意见的论文证据 |
| `SEARCH_PRIOR_ART` | 搜索先行研究 |
| `RELATION_CHECK` | 判断先行研究与目标主张的关系 |
| `COUNTERFACTUAL_SEARCH` | 执行反事实检索，主动寻找反证 |
| `CITATION_EXPAND` | 沿候选论文参考文献向前扩展一跳 |
| `STABILITY_TEST` | 测试结论是否稳定 |
| `FINALIZE_EVIDENCE` | 冻结证据，停止继续修改 |

这里的几个英文词分别表示：

- `Graph`：图谱；
- `Calibrate`：校准；
- `Run`：运行；
- `Internal`：内部的；
- `Validate`：验证；
- `Search`：搜索；
- `Prior Art`：先行研究，也就是在目标论文之前已经出现的相关工作；
- `Relation`：关系；
- `Check`：检查；
- `Counterfactual`：反事实，即主动假设作者的强主张可能不成立并寻找反证；
- `Citation`：引用；
- `Expand`：扩展；
- `Stability`：稳定性；
- `Test`：测试；
- `Finalize`：完成并冻结。

证据主管不能自由发明新的工具，也不能无限搜索。

---

### 模块六：论文内部评审器

论文内部评审器的英文名称是 `Internal Critic`。

- `Internal`：内部的；
- `Critic`：批评者或评审器。

它负责只根据目标论文本身检查：

- 论文做了什么；
- 方法是否清楚；
- 实验设计是否合理；
- 对照方法是否充分；
- 表格和数字是否支持结论；
- 是否缺少消融或稳健性实验；
- 是否存在复现问题；
- 作者是否过度解释结果。

正式版本中，这个模块由 `ASPR-Qwen` 完成。

`Qwen` 是通义千问大模型系列的英文名称。`ASPR-Qwen` 指为 ASPR 审稿任务专门训练或配置的 Qwen 模型。

这是第一处重要的大模型调用。

它的输入是：

- 论文中间表示；
- 论文主张；
- 方法与结果段落；
- 安全的图谱上下文。

它的输出不是最终报告，而是一份结构化内部评审草稿，包括：

- 贡献摘要；
- 创新性支持意见；
- 创新性限制意见；
- 优点；
- 缺点；
- 给作者的问题；
- 每条意见引用的论文证据编号。

本次测试暂时没有 ASPR-Qwen，因此使用 `Human Reconstruction Replay Critic` 代替。

这个名称可以拆成：

- `Human`：人类；
- `Reconstruction`：重建；
- `Replay`：回放；
- `Critic`：评审器。

它表示“把已经重建好的人类评审结果当作内部评审器的输出进行回放”。

本次回放只用于测试后续流程，不能代表 ASPR-Qwen 的能力。

---

### 模块七：外部先行研究引擎

外部先行研究引擎负责查找论文之外的证据。

它主要回答：

> 作者声称的创新，到底有没有更早的工作已经做过？

它包括四个小步骤。

#### 第一步：查询规划

查询规划器的英文名称是 `Query Planner`。

- `Query`：查询语句；
- `Planner`：规划器。

它会为一个主张生成两类普通查询：

1. 关键词查询；
2. 机制查询。

关键词查询关注论文原词，机制查询关注方法真正做了什么。

第一版查询规划是确定性程序，不调用大模型。

#### 第二步：科学文献检索

系统使用：

- `OpenAlex`：开放的全球学术文献数据库；
- `Semantic Scholar`：语义学术搜索服务。

检索结果会保存到本地缓存。

`Cache` 中文是“缓存”，意思是已经查过的结果保存下来，下次不必重复联网请求。

所有文献必须经过时间过滤：

> 只有早于审稿截止日期的论文，才可能成为有效先行研究。

#### 第三步：关系分类

关系分类器的英文名称是 `Relation Classifier`。

- `Relation`：关系；
- `Classifier`：分类器。

这是第二处重要的大模型调用。

大模型同时读取：

1. 目标论文的主张原文；
2. 候选先行论文的摘要或全文段落。

然后判断二者属于什么关系：

| 关系名称 | 中文含义 |
|---|---|
| `DIRECT_ANTECEDENT` | 直接先行研究：更早的工作已经直接做过核心内容 |
| `PARTIAL_ANTECEDENT` | 部分先行研究：更早工作做过核心内容的一部分 |
| `EXTENSION` | 扩展关系：当前论文主要是在已有工作上扩展 |
| `PARALLEL` | 平行关系：相近时间独立出现的相似工作 |
| `SUPPORT` | 支持关系：相关工作支持某个背景或判断 |
| `CONFLICT` | 冲突关系：相关工作与目标论文的结论不一致 |
| `DISTANT` | 关系较远：只有表面相似，不能作为直接先行研究 |
| `UNRESOLVED` | 尚未解决：证据不足，无法可靠判断 |

`Antecedent` 的意思是“先于某事发生的前项”，在这里就是“先行研究”。

关系分类必须有两侧证据：

- 目标论文段落；
- 先行论文段落。

只有标题相似，不能判定为先行研究。

#### 第四步：反事实检索

反事实检索的英文名称是 `Counterfactual Search`。

它不会顺着作者的说法寻找支持，而是主动问：

> 如果作者的“首次”“突破”主张不成立，可能是哪篇更早的工作已经做过？

例如作者把方法命名为“新型结构感知网络”，普通搜索可能只搜索这个新名称。反事实搜索会去掉包装名称，改为搜索：

- 它解决的真实问题；
- 它采用的核心机制；
- 相同机制的其他叫法；
- 更早的替代实现。

以下情况必须触发反事实搜索：

- 作者使用“首次”“前所未有”“突破性”等强主张；
- 内部评审意见支持论文创新性；
- 该意见是重大意见；
- 图谱信号和文本证据存在矛盾。

反事实检索后，候选论文仍需再次调用关系分类大模型。

### 模块八：图谱先验

图谱先验的英文名称是 `Graph Prior`。

- `Graph`：图谱；
- `Prior`：先验信息，也就是在进一步检查之前提供的辅助信号。

它使用当前 Fig.1–Fig.3 的图谱与预测资产。

`Fig.` 是 `Figure` 的缩写，中文是“图”。所以 `Fig.1–Fig.3` 就是当前论文的图 1 到图 3。

图谱会形成一个 `Calibration Packet`，中文是“校准数据包”。

其中可能包括：

- 论文发表前的结构特征；
- 潜在传播信号；
- 相对位置；
- 特征覆盖率；
- 数据漂移提示；
- 图谱是否适用于这篇论文。

`Calibration` 是“校准”。

`Packet` 是“数据包”。

`Drift` 是“漂移”，表示新论文与训练数据分布可能不一样。

图谱有四种适用状态：

| 状态 | 中文解释 |
|---|---|
| `exact_lookup` | 精确查表：该论文在冻结正式数据中有完全对应记录 |
| `eligible_inference` | 符合条件的推断：可以基于投稿时信息进行推断 |
| `profile_only` | 只有结构画像：只能描述特征，不能给完整预测 |
| `unavailable` | 不可用：数据或条件不足 |

图谱可以做的事：

- 调整哪些主张先查；
- 决定是否增加反事实检索；
- 提醒文本判断和图谱信号不一致；
- 调整检索预算；
- 要求进行稳定性测试；
- 让最终措辞更谨慎。

图谱不能做的事：

- 证明论文具有创新性；
- 证明论文质量高；
- 推翻直接先行研究；
- 证明论文应该被录用；
- 证明论文未来一定有巨大影响。

一句话理解：

> 图谱负责提醒“哪里值得多查”，不负责决定“论文到底新不新”。

---

### 模块九：证据验证器和稳定性测试

证据验证器的英文名称是 `Evidence Verifier`。

- `Evidence`：证据；
- `Verifier`：验证器。

它包括两种检查。

#### 确定性检查

确定性检查不调用大模型，它检查：

- 论文身份是否一致；
- 文件哈希值是否一致；
- 证据编号是否存在；
- 先行研究是否早于截止日期；
- 重大意见是否有证据；
- 图谱是否被错误当成创新性证据；
- 是否出现“接收”“拒稿”等编辑决定语言；
- 是否超过检索预算；
- 未解决意见是否被错误保留。

`Hash` 中文是“哈希值”，可以把它理解为文件的数字指纹。文件内容改变一个字符，哈希值通常也会改变。

#### 语义证据检查

语义证据检查是第三处重要的大模型用途。

它的英文名称是 `Semantic Evidence Verification`。

- `Semantic`：语义的，也就是关注一句话真正表达的意思；
- `Verification`：验证。

大模型会判断：

> 这条评审意见，是否真的被它引用的论文段落支持？

例如评审意见说：

> 作者没有报告统计显著性。

但引用段落实际上报告了置信区间和显著性检验，那么这条意见应当被判定为“不受证据支持”。

#### 稳定性测试

稳定性测试的英文名称是 `Stability Test`。

它检查结论是否过度依赖某一条证据。

包括：

1. 删除最强先行研究后，结论是否翻转；
2. 普通检索与反事实检索是否互相冲突；
3. 移除图谱信号后，创新性语义判断是否改变。

如果移除图谱后“论文是否创新”的判断改变，说明系统错误地依赖了图谱。

高风险意见如果稳定性不通过，会被标记为“尚未解决”，不会进入最终报告。

---

### 模块十：过程诊断、评审编译器与最终输出

#### 过程诊断

过程诊断的英文名称是 `Process Diagnostic`。

- `Process`：过程；
- `Diagnostic`：诊断信息。

它会总结：

- 检索是否完成；
- 找到多少独立来源；
- 是否存在关系冲突；
- 是否完成反事实搜索；
- 反事实搜索是否改变判断；
- 稳定性是否通过；
- 图谱是否适用；
- 验证器是否通过；
- 哪些外部服务失败。

当前阶段只输出三种状态：

- `sufficient`：过程证据基本充分；
- `limited`：过程有限，部分环节没有完成；
- `unavailable`：关键能力不可用。

这里：

- `Sufficient`：充分；
- `Limited`：有限；
- `Unavailable`：不可用。

当前不会输出“可信度 93%”一类数字，因为尚未训练正式的置信度校准模型。

#### 评审编译器

评审编译器的英文名称是 `Review Compiler`。

它不调用大模型，也不创造新意见。

它只把通过验证的评审状态整理成最终报告。

可以进入报告的状态：

- `VALIDATED`：已经通过论文内部证据验证；
- `EXTERNALLY_VALIDATED`：已经通过外部证据验证。

不能进入报告的状态：

- `PENDING`：等待处理；
- `UNRESOLVED`：证据不足，尚未解决；
- `REJECTED`：已拒绝，不应保留。

#### 最终输出检查器

最终输出检查器的英文名称是 `Output Linter`。

- `Output`：输出；
- `Linter`：静态检查器，负责查找格式或规则错误。

它最后检查：

- 是否只有规定的五个部分；
- 是否有有效证据编号；
- 是否出现接收或拒稿语言；
- 是否泄漏了不应写进报告的图谱术语；
- 论文身份是否正确；
- 输出清单和哈希值是否完整。

它只检查，不再修改内容。

## 4. 一篇论文从输入到输出的完整过程

下面按实际发生顺序说明。

### 第 1 步：接收论文和元数据

系统接收论文、DOI、投稿日期和其他元数据。

`Metadata` 中文是“元数据”，也就是描述论文身份的信息。

### 第 2 步：冻结时间边界

系统确定审稿截止日期。

以后检索的先行研究必须早于这个日期。没有日期的候选文献不能被当成强先行研究。

### 第 3 步：构建论文中间表示

正式模式运行论文编译器；本次测试加载冻结的 `paper_ir.json`。

系统验证论文身份、哈希值、段落编号和段落文本。

### 第 4 步：抽取主张和方法结果清单

系统找出：

- 创新性主张；
- 方法主张；
- 结果主张；
- 因果主张；
- 适用范围主张；
- 重要性主张。

### 第 5 步：生成论文专属检查表

系统根据论文类型和实际内容，列出需要检查的项目。

### 第 6 步：建立空评审状态

这时评审状态中还没有评审意见，只有：

- 论文；
- 检查表；
- 主张；
- 时间边界；
- 空的证据槽位；
- 检索预算。

### 第 7 步：证据主管启动图谱分支

系统构建当前 Fig.1–Fig.3 图谱校准数据包，并判断图谱是精确可用、可推断、仅画像还是不可用。

### 第 8 步：证据主管启动内部评审

正式版本调用 ASPR-Qwen。

本次测试读取 100 篇人工重建结果中的结构化评审。

输出进入评审状态，但还不是最终报告。

### 第 9 步：验证每条内部意见的论文证据

没有有效论文段落编号的意见直接拒绝。

普通内部意见可以在这一阶段通过。创新性和先行研究意见必须继续查外部证据。

### 第 10 步：把评审意见绑定到论文主张

系统确认一条创新性意见到底在讨论哪个作者主张。

### 第 11 步：执行普通先行研究检索

查询规划器生成关键词查询和机制查询，然后访问 OpenAlex 或 Semantic Scholar。

### 第 12 步：进行时间过滤

晚于或等于截止日期的不合格文献被丢弃，防止使用未来信息。

### 第 13 步：调用关系分类大模型

大模型读取目标主张和候选文献证据，生成关系卡。

`Relation Card` 中文是“关系卡”，是对两篇论文之间关系的结构化记录。

### 第 14 步：判断是否属于高风险主张

系统检查它是否是强主张、重大意见、创新性支持意见，或者是否存在图谱与文本冲突。

### 第 15 步：必要时执行反事实检索

系统主动寻找能够推翻“首次”“突破”主张的更早工作，然后再次调用关系分类大模型。

### 第 16 步：必要时进行一跳引用扩展

如果证据仍不明确，系统沿最合适候选论文的参考文献向前扩展一次，并再次判断关系。

### 第 17 步：执行证据充分性判断

支持创新性的意见要求更严格：至少两个独立来源、没有直接先行研究、完成反事实搜索、两侧证据完整。

限制创新性的意见至少需要一条有效的直接、部分先行研究或扩展关系。

### 第 18 步：执行稳定性测试

系统检查判断是否因为单条证据或图谱信号而轻易翻转。

### 第 19 步：停止或继续

如果还有必须解决的证据缺口，而且还有预算，证据主管继续选择动作。

如果预算耗尽，剩余问题标记为“尚未解决”，不会强行猜测。

### 第 20 步：冻结证据状态

一旦执行证据冻结，系统不再允许新增检索结果和关系卡。

### 第 21 步：运行证据状态验证器

系统先运行确定性检查，再调用大模型做语义证据检查。

### 第 22 步：最多进行一次删除式修复

如果某条具体意见无法被证据支持，系统可以把它删除，然后重新验证一次。

系统不能让大模型重新改写这条意见，因为改写可能产生新的错误。

### 第 23 步：生成过程诊断

系统说明本次证据流程是充分、有限还是不可用，并列出原因。

### 第 24 步：编译最终报告

评审编译器只读取已经通过验证的意见，形成五部分报告：

1. 贡献摘要；
2. 创新性分析；
3. 优点；
4. 缺点；
5. 给作者的问题。

### 第 25 步：执行最终输出检查

检查格式、证据、身份、图谱语义和禁止语言。

### 第 26 步：保存完整运行包

系统输出人类可读报告和机器可读证据链。

## 5. 哪些地方需要调用大模型

当前设计中，大模型只在明确位置使用。

| 调用位置 | 使用什么模型 | 输入 | 输出 | 当前测试是否调用 |
|---|---|---|---|---|
| 论文内部评审 | 正式使用 ASPR-Qwen | 目标论文的主张、方法、结果和证据段落 | 结构化内部评审草稿 | 否，当前使用人工重建回放 |
| 普通候选关系分类 | Codex 或其他结构化大模型 | 目标主张段落与候选先行论文段落 | 关系卡 | 是 |
| 反事实候选关系分类 | Codex 或其他结构化大模型 | 目标主张与反事实候选证据 | 关系卡 | 是 |
| 引用扩展关系分类 | Codex 或其他结构化大模型 | 目标主张与更早引用文献证据 | 关系卡 | 是 |
| 语义证据验证 | Codex 或其他验证模型 | 评审意见与其引用的论文段落 | 支持或不支持 | 是 |

`Codex` 是 OpenAI 面向编程和复杂任务执行的智能模型。在这里，它不是用于写代码，而是作为结构化关系判断器和语义验证器。

不会调用大模型的模块包括：

- 论文身份验证；
- 时间过滤；
- 论文专属检查表第一版；
- 查询规划第一版；
- 图谱模型计算；
- 证据预算；
- 稳定性规则；
- 评审编译；
- 最终输出检查；
- 文件哈希和运行清单验证。

## 6. 系统如何保存证据

原始证据保存在 `EvidenceStore` 中。

- `Evidence`：证据；
- `Store`：存储库。

它是一个只能追加、不能覆盖的证据仓库。

不同证据使用不同前缀：

| 前缀 | 含义 | 示例 |
|---|---|---|
| `P:` | 目标论文内部证据 | `P:S-abc123` |
| `W:` | 检索到的外部论文 | `W:C-001:W123` |
| `R:` | 目标主张与先行论文的关系证据 | `R:REL-xyz` |
| `G:` | 图谱校准证据 | `G:CP:profile` |
| `D:` | 内部评审草稿 | `D:paper-id` |

状态中一般只保存这些证据编号，不重复复制大段原文。

系统还保存：

- `Action Trace`：动作轨迹，记录每次做了什么；
- `State Trace`：状态轨迹，记录每次状态如何变化；
- `Run Manifest`：运行清单，记录所有输入输出文件和哈希值。

这里：

- `Action`：动作；
- `Trace`：轨迹；
- `Run`：一次完整运行；
- `Manifest`：清单。

## 7. 系统为什么会输出“有限结果”

系统采用 `Fail Closed` 原则。

- `Fail`：失败；
- `Closed`：关闭或拒绝放行；
- `Fail Closed`：失败时不猜测、不伪造成功，而是明确给出有限结果。

以下情况可能使结果变成“有限”：

- 论文解析质量不足；
- 图谱不可用；
- 外部文献服务失败；
- 关系分类模型不可用；
- 先行文献缺少日期；
- 先行文献只有标题，没有摘要或全文证据；
- 反事实检索没有完成；
- 重大意见没有证据；
- 稳定性测试不通过；
- 语义验证器失败；
- 预算耗尽后仍有关键问题未解决；
- 最终输出检查不通过。

“有限”不等于“论文质量低”，只表示：

> 这次系统运行没有获得足够证据来给出完整可靠结果。

## 8. 当前 100 篇测试究竟能证明什么

当前使用 100 篇 Nature 人工评审重建结果，代替 ASPR-Qwen 的内部评审输出。

它可以证明：

- 整个状态流程可以运行；
- 证据主管可以调度各个模块；
- 图谱分支可以接入；
- 外部文献检索可以接入；
- 关系分类可以运行；
- 反事实搜索可以触发；
- 稳定性测试可以运行；
- 不可靠意见可以被过滤；
- 最终报告和证据链可以生成；
- 100 篇批处理可以被审计。

它不能证明：

- ASPR-Qwen 能够生成这些意见；
- ASPR-Qwen 与人类评审一致；
- ASPR-GEAR 已经超过人类；
- ASPR-GEAR 已经超过 ReviewGrounder；
- 系统已经具备正式论文中可以声明的性能。

因此所有测试输出必须标记：

```text
仅限开发测试
禁止用于能力评价
禁止用于人机一致性评价
```

## 9. 最终输出包括什么

人类主要阅读：

- `review.md`：最终同行评审报告。

机器和研究人员可以检查：

- `paper_ir.json`：论文中间表示；
- `calibration_packet.json`：图谱校准数据包；
- `review.json`：结构化最终评审；
- `validation_report.json`：验证报告；
- `review_bundle.json`：完整评审运行包；
- `evidence_trace.jsonl`：证据轨迹；
- `action_trace.jsonl`：动作轨迹；
- `state_trace.jsonl`：状态轨迹；
- `run_manifest.json`：运行清单。

`JSON` 是结构化数据格式，适合程序读取。

`JSONL` 是每一行一个 JSON 对象的格式，适合保存不断追加的轨迹记录。

## 10. 最简洁的总流程

如果前面的内容太多，只需要记住下面十二句话：

1. 论文进入系统后，先被拆成带编号的证据段落。
2. 系统根据论文内容生成专属检查表。
3. 系统建立一份空的统一评审台账。
4. 证据主管决定下一步调用哪个能力。
5. ASPR-Qwen 负责检查论文内部，但它不直接写最终报告。
6. 外部检索负责寻找真正的先行研究。
7. 大模型关系分类器负责比较目标主张和先行论文。
8. 强创新性主张必须进行反事实检索。
9. 图谱只决定哪里需要重点检查，不能证明论文创新。
10. 所有高风险判断都要进行稳定性测试。
11. 没有证据或验证失败的意见不能进入最终报告。
12. 最终报告中的每条重要意见都可以追溯到论文或先行研究证据。

## 12. 一句话结论

ASPR-GEAR 不是“让一个大模型自动写审稿意见”，而是：

> 让证据主管围绕统一评审状态，调度 ASPR-Qwen、先行研究检索、关系比较和图谱校准，再由验证器淘汰无证据或不稳定的意见，最后把通过验证的内容编译成可追溯的同行评审报告。
