## 4. Evidence Monitor 最小规则

```python
def next_action(claim):
    if claim.retrieval_coverage < 0.70:
        return "SEARCH_PRIOR_ART"

    if claim.strength in {"first", "breakthrough", "unprecedented"} \
       and not claim.counterfactual_search_done:
        return "COUNTERFACTUAL_SEARCH"

    if claim.evidence_conflict:
        return "RELATION_CHECK"

    if claim.novelty_judgment and claim.stability is None:
        return "STABILITY_TEST"

    return "VERIFY"
```

阈值不应长期拍脑袋固定，后续用 validation set 校准。

## 8. Process confidence 第一版不用训练神经模型

特征：

```text
retrieval_coverage
relation_confidence
number_of_independent_prior_sources
evidence_conflict
counterfactual_search_change
stability_score
graph_confidence
verifier_pass_rate
```

先做 Logistic Regression / Isotonic Regression / Platt scaling 等简单校准器即可，前提是你有人工标注的 claim-level correct/incorrect 标签。

没有训练集时先用透明规则，不要让 LLM 直接声称 0.93 confidence。

## 9. 最终输出的引用追溯

每个 major review statement 保存：

```text
Review Sentence ID
→ Review State Entry ID
→ Claim ID / Weakness ID
→ Paper Span / Prior Paper Span / ScorePacket Field
→ DOI / Paper ID
```

最终界面或 JSON 可以同时返回 `trace`，自然语言报告只显示简洁 citation。

## 10. 日志保留什么

保留：

- controller action；
- query；
- tool result ids；
- state diff；
- verifier result。

不要把所有自然语言 reasoning 作为核心状态。

## 11. 最重要的工程边界

1. 事实进入 Review State 前必须有 source id。
2. Reviewer Composer 不允许直接调用检索工具。
3. Evidence Controller 不允许直接修改最终 review 文本。
4. Graph Tool 不允许产生论文作者没有声明的 contribution。
5. 时间截止必须在 retrieval 层强制过滤，而不是只写进 prompt。
6. `unavailable` 与 `low` 必须严格区分。
