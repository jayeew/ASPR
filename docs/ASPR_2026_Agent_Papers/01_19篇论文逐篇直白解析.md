## A 级：直接决定 ASPR 主架构的论文

## 1. Beyond “Not Novel Enough”: Enriching Scholarly Critique with LLM-Assisted Feedback

**会议：EACL 2026**  
**文件：`01_Beyond_Not_Novel_Enough_EACL2026.pdf`**

### 一句话先讲懂

这篇论文专门研究“怎么让 LLM 判断一篇论文到底新不新”，而且它没有堆很多 Reviewer Agent，而是把创新性评价拆成三个很清楚的阶段：**先提取论文贡献，再查相关工作，最后做结构化比较。**

### 它解决什么问题

普通 LLM 很容易看到摘要以后直接说“有一定创新”“创新不足”，但没有真正完成真人审稿人最重要的动作：

1. 论文到底声称了什么新东西；
2. 最接近的已有工作是什么；
3. 论文和已有工作真正差在哪里。

这篇工作把 novelty assessment，也就是**创新性评价**，显式拆解成：

- `content extraction`：内容提取，把论文真正的贡献点提出来；
- `retrieval and synthesis`：检索并归纳相关研究；
- `structured comparison`：结构化比较，不让模型只做泛泛评价。

### 关键英文词

- **Novelty assessment**：创新性评价。不是论文总质量，而是“这个贡献相对于已有研究有多新”。
- **Retrieval**：检索。从数据库中找到相关论文。
- **Synthesis**：综合归纳。不是简单列论文，而是把几篇论文到底做了什么合并成有逻辑的相关工作认识。
- **Structured comparison**：结构化比较。要求模型按照固定字段比较，例如“已有方法 / 本文方法 / 共同点 / 差异 / 是否已经覆盖核心主张”。
- **Evidence-based assessment**：基于证据的评价。结论必须能回到具体文献或论文内容。

### 与 ASPR 的相似点

它与 Graph-grounded ASPR 的主任务几乎是同类问题。你的系统已经比它多了一个很重要的东西：**发表前知识图谱的结构性校准信号。**

因此它非常适合做 ASPR 的直接 baseline（基线，也就是对照方法）。

### ASPR 最值得借什么

不要再把 Claim Decomposer、Evidence Mapper、Skeptic 等视为必须独立存在的 Agent。可以把创新性分支直接收敛成：

`Contribution Extraction → Prior-art Retrieval → Structured Claim Comparison → Graph Calibration`

其中只有“结构化比较”真正需要强 LLM 推理。

### 不建议照搬什么

不要停留在 paper-level“这篇论文和那篇论文相似”。ASPR 应进一步做到 claim-level（主张级）甚至 evidence-span-level（具体证据片段级）。

**推荐度：★★★★★，核心必读。**

## 2. ReviewGrounder: Improving Review Substantiveness with Rubric-Guided, Tool-Integrated Agents

**会议：ACL 2026**  
**文件：`02_ReviewGrounder_ACL2026.pdf`**

### 一句话先讲懂

这篇论文和 ASPR 的最终任务最像：它认为 LLM 已经会“写得像审稿”，真正缺的是**具体、深入、能落到证据上的审稿内容**，因此先生成草稿，再用工具和证据去补强，并用针对当前论文的 rubric 控制质量。

### 它解决什么问题

很多 AI review 看起来格式完整：summary、strengths、weaknesses 都有，但评论很空，例如：

> “实验还可以更全面。”

真正好的审稿应该说：

> “表 3 只与 A/B 比较，而与最接近的 C 缺少统一设置对比，因此当前性能优势不能排除 baseline selection 的影响。”

这就是论文所说的 **substantiveness**。

### 关键英文词

- **Substantiveness**：实质性。不是“话多”，而是评论具体、有依据、有真正技术内容。
- **Rubric**：评分准则/检查清单。例如当前论文是否充分比较相关工作、实验是否有消融、结论是否被实验支持。
- **Rubric-guided**：由评分准则引导。模型不是自由发挥，而是对照当前论文应该检查的项目逐项检查。
- **Tool-integrated**：工具增强。模型可以调用文献检索、论文段落定位等工具。
- **Drafting**：起草阶段。
- **Grounding**：证据落地/证据补强。把草稿中的泛泛判断绑定到论文内容或外部文献。

### 与 ASPR 的相似点

它的 `drafter → grounding` 与你的 `ASPR-Qwen → Graph-grounded evidence fusion` 很像。

但 ASPR 的优势更明显：你已经拥有独立的创新性图谱证据，不只是工具检索。

### ASPR 最值得借什么

**引入 Paper-specific Review Rubric（针对当前论文动态生成的审稿检查表）。**

例如一篇纯理论论文和一篇深度学习实验论文不应该使用完全相同的检查项。

Paper Analyzer 在开始时生成：

- novelty rubric；
- methodology rubric；
- experimental rubric；
- reproducibility rubric；
- evidence rubric。

随后 ASPR-Qwen 和外部证据分支都围绕 rubric 填写 Review State。

### 不建议照搬什么

不需要复制它的多 Agent 角色。ASPR 可以保留它的“草稿—证据补强”思想，但把核心状态改成统一 Review State。

**推荐度：★★★★★，核心必读。**

## 3. Eigen-Agent: Adaptive Multi-Agent Scientific Reasoning with Monitor-Based RAG

**会议：ICLR 2026**  
**文件：`03_Eigen-Agent_ICLR2026.pdf`**

### 一句话先讲懂

它最值得借的不是多 Agent，而是一个非常关键的思想：**不要一开始把所有知识搜完；系统在推理过程中发现“这里我不知道”时，再触发检索。**

### 它解决什么问题

普通 RAG 往往：

`先搜一批资料 → 全塞给模型 → 开始回答`

但真正研究任务里，模型通常是在比较和推理以后才知道自己缺什么。例如 ASPR 第一轮检索完以后，才发现：

> “作者声称首次把 X 用到 Y，但目前检索结果都只覆盖 X，不知道 2021 年以前是否已有 X+Y。”

这时候应该继续查，而不是直接写 conclusion。

### 关键英文词

- **RAG (Retrieval-Augmented Generation)**：检索增强生成。让模型在回答前或回答过程中读取外部资料。
- **Monitor-based RAG**：监控器驱动的 RAG。由一个 Monitor 判断是否出现知识缺口，再决定是否检索。
- **Monitor**：监控器。它不是 Reviewer，而是判断当前推理状态是否缺证据。
- **Knowledge gap**：知识缺口。当前信息不足以支持下一步判断。
- **Adaptive**：自适应。根据当前状态改变后续动作，而不是固定工作流。
- **Hierarchical Solution Refinement (HSR)**：分层解答精炼。逐层挑选和修正候选解。
- **Quality-Aware Iterative Reasoning (QAIR)**：质量感知的迭代推理，根据当前解质量决定如何继续改。

### ASPR 最值得借什么

增加一个**Evidence-Gap Monitor（证据缺口监控器）**，但不必复制 Eigen-Agent 的整套多 Agent 推理。

对每条 novelty claim，只需要判断：

- 当前先行研究覆盖充分吗；
- 最接近论文明确吗；
- 文献之间有冲突吗；
- 是否出现 first/首次/突破 等强主张；
- graph evidence 是否可用；
- 当前结论对关键证据是否敏感。

然后输出动作：

`PASS / SEARCH_AGAIN / COUNTERFACTUAL_SEARCH / SECOND_CHECK`

这就能让 ASPR 从固定流水线变成真正的 agentic system（智能体式系统）。

**推荐度：★★★★★。**

## 4. IterResearch: Rethinking Long-Horizon Agents with Interaction Scaling

**会议：ICLR 2026**  
**文件：`05_IterResearch_ICLR2026_AuthorVersion.pdf`**

### 一句话先讲懂

不要把 Agent 从第一步到最后一步的所有对话、搜索结果、反思都一直塞进上下文；应该不断维护一个**最新、压缩、经过整理的工作状态**。

### 它解决什么问题

研究型 Agent 一旦执行几十次搜索，历史上下文会越来越长：

- 旧的错误结果还留着；
- 重复内容越来越多；
- 真正重要的证据被淹没；
- 模型越来越难集中注意力。

论文称这种问题为 `context suffocation`。

### 关键英文词

- **Long-horizon agent**：长周期智能体。需要很多轮工具调用才能完成任务的 Agent。
- **Context suffocation**：上下文窒息。历史信息越来越多，把模型当前推理空间挤满。
- **Noise contamination**：噪声污染。早期无关/错误信息一直留在上下文并影响后面推理。
- **Workspace reconstruction**：工作区重建。定期把历史重新整理成一个干净的当前状态。
- **Evolving report**：不断演化的报告/工作记忆。每轮更新，而不是不断追加完整历史。
- **Markovian / MDP-inspired state**：马尔可夫式状态。直白理解：下一步主要依赖“现在这个整理好的状态”，而不是必须重读全部过去。

### ASPR 最值得借什么

把 Review Ledger 从“结果存档”升级成**系统唯一可信的工作状态（source of truth）**。

以后所有模块都读取：

`Target Paper + Current Review State`

执行完以后更新 Review State，而不是让下一个 Agent 读取前面所有人的聊天记录。

这会大幅简化你的系统，同时减少提示词长度和错误传播。

**推荐度：★★★★★。**

## 5. SciNet: Evaluating AI Agents in Relation-Aware Scientific Literature Retrieval

**会议：ICML 2026**  
**文件：`09_SciNet_ICML2026_AuthorVersion.pdf`**

### 一句话先讲懂

检索相关论文不能只问“哪篇论文语义最像”，还应该问：**两篇论文到底是什么关系——谁先提出、谁扩展谁、谁支持谁、谁冲突谁、技术路线怎么演化。**

### 它解决什么问题

Embedding（向量语义相似度）擅长找“主题相似”，但创新评价真正关心的是：

- A 是否已经做过 B 的核心贡献；
- B 是扩展 A，还是完全不同路线；
- 两篇论文是支持、冲突还是平行发展；
- 某个方法如何沿引用网络演化。

SciNet 把科学文献检索从 content-level similarity（内容相似度）提升到 relation-aware retrieval（关系感知检索）。

### 关键英文词

- **Relation-aware retrieval**：关系感知检索。不只找相似文献，还识别文献之间的关系。
- **Ego-centric relation**：以单篇论文为中心的关系，例如这篇论文在知识结构中是否异常/新颖。
- **Pair-wise relation**：论文两两关系，例如支持、反驳、扩展。
- **Path-wise relation**：路径关系，例如 A→B→C 形成技术演化链。
- **Technological lineage**：技术谱系/技术沿袭。一个方法从哪些前身逐步演化而来。
- **Corroborating**：相互支持、相互印证。
- **Conflicting**：相互冲突。

### ASPR 最值得借什么

这是当前 ASPR 检索部分最应该升级的点之一。

现在：

`claim → Top-k similar papers`

建议变成：

`claim → Top-k candidates → relation classification`

关系可以简化成：

- `ANTECEDENT`：已有工作已经覆盖核心思想；
- `PARTIAL_PRECEDENT`：部分已有；
- `EXTENSION_BASE`：本文是在它基础上扩展；
- `SUPPORTING`：支持本文动机/结论；
- `CONFLICTING`：与本文结论冲突；
- `PARALLEL`：相近时期独立路线；
- `DISTANT`：仅主题相似。

这比继续微调 embedding 相似度更有科研价值。

**推荐度：★★★★★。**

## 6. Counterfactual Reasoning for Retrieval-Augmented Generation (CF-RAG)

**会议：ICLR 2026**  
**文件：`07_CF-RAG_ICLR2026.pdf`**

### 一句话先讲懂

普通检索会不断找到“看起来相关”的证据；CF-RAG 提醒我们要主动问：**如果我改变查询条件，结论还成立吗？有没有被当前关键词遮住的反例？**

### 关键英文词

- **Counterfactual**：反事实。直白理解：主动构造“如果条件换一下，会怎样”的查询。
- **Counterfactual query**：反事实查询。不是重复原搜索，而是改变关键条件、术语或假设。
- **Correlation Trap**：相关性陷阱。搜到很多表面相关资料，却没有找到真正决定结论的证据。
- **Arbitration**：仲裁。当不同证据互相冲突时，明确比较并决定哪些证据更关键。

### ASPR 最值得借什么

把以前过重的“Novelty Falsifier Agent”简化成一个**Counterfactual Prior-Art Search（反事实先行研究搜索）**动作。

只对高风险主张触发：

- `first / 首次`；
- `unprecedented / 前所未有`；
- `breakthrough / 突破性`；
- 首轮检索置信度低；
- prior papers 相互冲突。

典型做法：

1. 去掉作者自己创造的新术语重新搜；
2. 用“任务 + 核心机制 + 应用场景”重新搜；
3. 强制 publication date < target paper；
4. 用近义词/旧术语替换作者术语；
5. 从最接近文献的引用链反向扩展。

这非常适合 ASPR，而且实现难度不高。

**推荐度：★★★★★。**

## 7. Stop Wasting Your Tokens: Towards Efficient Runtime Multi-Agent Systems

**会议：ICLR 2026**  
**文件：`08_SupervisorAgent_ICLR2026_AuthorVersion.pdf`**

### 一句话先讲懂

不要让监督 Agent 每一步都参与。用一个轻量过滤器判断“现在是不是风险节点”，只有风险高时 Supervisor 才介入。

### 关键英文词

- **Runtime supervision**：运行时监督。系统执行过程中实时看是否出现问题。
- **SupervisorAgent**：监督智能体。不是做主任务，而是监督其他流程是否正在走偏。
- **Adaptive filter**：自适应过滤器。先用低成本规则/模型判断是否值得调用昂贵 Supervisor。
- **Intervention**：干预。只有需要时才纠错、调整路线或清理输入。
- **Observation purification**：观察净化。把工具返回的长而杂的信息压缩成真正有用的内容。
- **Post-hoc**：事后。失败以后才分析；论文强调主动在失败前干预。

### ASPR 最值得借什么

Evidence-First ASPR 最适合只保留**一个真正的 Controller Agent：Evidence Supervisor。**

它不写 review，只决定下一步动作：

- `CONTINUE`；
- `SEARCH_AGAIN`；
- `COUNTERFACTUAL_SEARCH`；
- `ASK_SPECIALIST`；
- `VERIFY`；
- `FINALIZE`。

而且 80% 普通 claim 可以规则直接 PASS，只有不确定或强 claim 才调用 Supervisor LLM。

这会让系统既有前沿 Agent 特性，又不会重新变得复杂。

**推荐度：★★★★★。**

## 8. Agentic Confidence Calibration

**会议：ICML 2026**  
**文件：`10_Agentic_Confidence_Calibration_ICML2026_AuthorVersion.pdf`**

### 一句话先讲懂

不要相信 Agent 最后一句“我有 90% 信心”。应该看它**整个执行过程**是否稳定、是否反复改答案、是否频繁失败、工具结果是否冲突，再判断它到底有多可靠。

### 关键英文词

- **Confidence calibration**：置信度校准。让“80% 信心”的样本真的大约有 80% 正确，而不是模型随口报数字。
- **Agentic confidence**：智能体置信度。针对多步工具调用 Agent 的可靠程度。
- **Trajectory**：执行轨迹。Agent 从开始到结束经历的搜索、工具调用、状态变化等完整过程。
- **Holistic Trajectory Calibration (HTC)**：整体轨迹校准。使用整个执行过程中的特征估计最终置信度。
- **Macro dynamics**：宏观动态，例如总搜索次数、重规划次数、答案是否不断改变。
- **Micro stability**：微观稳定性，例如局部步骤置信信号是否稳定。
- **OOD (Out-of-distribution)**：分布外。遇到和训练数据不同的新任务。

### ASPR 最值得借什么

不要复制论文几十维轨迹特征。做轻量版即可：

`claim_confidence = f(retrieval_coverage, prior_art_agreement, relation_conflict, counterfactual_search_delta, graph_confidence, qwen_external_consistency, verifier_status, judgment_stability)`

重点是把 uncertainty 从“Meta Reviewer 主观说 medium”改成可观察过程信号。

**推荐度：★★★★★。**

## 9. When Planning Fails Despite Correct Execution: On Epistemic Calibration for LLM-Based Multi-Agent Systems

**会议：ICML 2026**  
**文件：`11_Epistemic_Calibration_ICML2026_AuthorVersion.pdf`**

### 一句话先讲懂

有时 Agent 每个步骤都执行正确，但整个任务仍然错，因为它错误地认为：**“我现在知道得已经够多，可以下结论了。”**

### 关键英文词

- **Epistemic**：认知/知识层面的。关注“系统知道什么、不知道什么”。
- **Epistemic calibration**：认知校准。判断系统是否正确认识到自己的知识是否足够。
- **Epistemic miscalibration**：认知失准。信息其实不够，但系统误以为够了。
- **Feasibility**：可行性。在已有信息下，当前计划是否真的足以完成目标。
- **Information consistency**：信息一致性。换一部分信息以后，判断是否还保持稳定。

### ASPR 最值得借什么

做一个非常简单但很有论文价值的 **Evidence Stability Test（证据稳定性测试）**。

例如对 novelty claim：

- 全证据 → High novelty；
- 去掉最接近 prior paper → High；
- 去掉 graph prior → Moderate；
- 换成 top-3 literature → Low。

这说明判断高度依赖某一条证据，应降低 confidence。

最终不仅输出：

`novelty = positive`

还输出：

`confidence = moderate; evidence_sensitivity = high`

这个机制非常适合 ASPR。

**推荐度：★★★★★。**

## 10. FlowSearcher: Synthesizing Memory-Guided Agentic Workflows for Web Information Seeking

**会议：ICLR 2026**  
**文件：`04_FlowSearcher_ICLR2026.pdf`**

### 一句话先讲懂

不同问题不应该使用完全相同的搜索流程；系统可以把问题拆成子目标，并复用过去成功的“怎么搜”经验。

### 关键英文词

- **Subgoal**：子目标。把大问题拆成几个明确小问题。
- **Workflow synthesis**：工作流合成。根据当前问题动态组合搜索步骤。
- **Hierarchical memory**：层级记忆。分别记住局部步骤、完整流程和任务级经验。
- **Orchestration**：编排。决定工具按什么顺序、以什么组合工作。

### ASPR 怎么借

不需要动态生成复杂 workflow。只做 **Search Strategy Memory（搜索策略记忆）**：

- `first claim` 常用哪些查询扩展；
- `new application` 怎么搜；
- `new mechanism` 怎么搜；
- 第一次只找到主题相似文献时，第二次怎么改 query。

存的是“搜索方法”，而不是旧论文的事实结论，这样更安全，也减少时间泄漏。

**推荐度：★★★★☆。**

## 11. MEM1: Learning to Synergize Memory and Reasoning for Efficient Long-Horizon Agents

**会议：ICLR 2026**  
**文件：`06_MEM1_ICLR2026.pdf`**

### 一句话先讲懂

Agent 不应该把完整历史一直带着，而应该把历史不断压缩进一个**compact shared internal state（紧凑共享内部状态）**。

### 关键英文词

- **Memory consolidation**：记忆整合。把零散历史压缩成更稳定的总结状态。
- **Compact internal state**：紧凑内部状态。只保留当前决策真正需要的信息。
- **Near-constant context size**：近似恒定上下文长度。任务变长时 prompt 不无限增长。
- **Reinforcement learning (RL)**：强化学习。通过奖励训练模型选择更好的行为。
- **Trajectory truncation**：轨迹截断。不必让训练/推理一直依赖完整历史。

### ASPR 怎么借

你不需要训练 MEM1。它更像是对 Review State 设计的理论支持：

> ASPR 的工作记忆应该是当前结构化评审状态，而不是 Agent 聊天历史。

**推荐度：★★★★☆。**

## 12. Graph-of-Agents: A Graph-based Framework for Multi-Agent LLM Collaboration

**会议：ICLR 2026**  
**文件：`12_Graph_of_Agents_ICLR2026.pdf`**

### 一句话先讲懂

多 Agent 系统不是“Agent 越多越好”。先根据当前问题选择真正有用的少数 Agent，再决定它们怎么交流。

### 关键英文词

- **Topology**：拓扑。Agent 之间谁连接谁、信息按什么路径流动。
- **Node sampling**：节点选择。从候选 Agent 中挑真正有用的几个。
- **Edge sampling**：边选择。决定被选 Agent 之间哪些需要通信。
- **Model card**：模型能力说明，例如某模型更擅长数学、代码、长文本。
- **Message passing**：消息传递。Agent 节点之间交换结果。
- **Graph pooling**：图聚合。把多个 Agent 的结果整合成最终答案。

### ASPR 怎么借

只借 `selective expert escalation`：**选择性专家升级。**

默认不启动专家；只有 Review State 触发：

- 复杂统计 → Statistics Expert；
- 强创新主张 → Novelty Second Opinion；
- 引用冲突 → Citation Expert；
- 方法细节高度专业 → Method Specialist。

这比固定五 Reviewer Committee 更合理。

**推荐度：★★★★☆。**

## 13. Agent Primitives: Reusable Latent Building Blocks for Multi-Agent Systems

**会议：ICML 2026**  
**文件：`16_Agent_Primitives_ICML2026_AuthorVersion.pdf`**

### 一句话先讲懂

不要把“角色 Agent”当成系统最基本单位。很多 Agent 系统其实可以拆成少数重复出现的**计算原语/功能积木**。

### 关键英文词

- **Primitive**：原语/基础积木。最小可复用功能模块。
- **Review Primitive**：评审原语，用于批评和修正一个候选结果。
- **Voting and Selection Primitive**：投票与选择原语，用于多个候选中选一个。
- **Planning and Execution Primitive**：规划与执行原语，先设计步骤再实际执行。
- **Latent communication**：潜空间通信。Agent 不一定用完整自然语言互聊，而在模型内部表示层传递信息。
- **KV cache**：Key-Value Cache，模型注意力计算时缓存的内部状态。论文用它减少自然语言通信的信息损耗和成本。
- **Organizer**：组织器，根据任务选择并组合原语。

### ASPR 怎么借

这是我认为可以支持“大胆重构”的一篇。

ASPR 不再设计：

`Claim Agent / Evidence Agent / Skeptic Agent / Meta Agent`

而改成几个**Review Primitives**：

- `EXTRACT`：提取论文结构和 claims；
- `RETRIEVE`：获得外部证据；
- `COMPARE`：对比 claim 与 prior art；
- `CRITIQUE`：检查方法和实验；
- `CHALLENGE`：反事实搜索或第二意见；
- `VERIFY`：验证证据和最终判断；
- `COMPOSE`：生成最终 review。

由 Evidence Controller 选择下一次调用哪个 Primitive。

KV-cache latent communication 对 ASPR 未必容易实现，尤其使用 API 模型时，所以只借“原语化系统设计”，不要硬搬潜空间通信。

**推荐度：★★★★☆，架构思想很值得借。**

## 14. ResearchRubrics: A Benchmark of Prompts and Rubrics For Evaluating Deep Research Agents

**会议：ICLR 2026**  
**文件：`18_ResearchRubrics_ICLR2026_AuthorVersion.pdf`**

### 一句话先讲懂

复杂研究报告不能只靠一个总分评价，需要把“事实是否正确、推理是否充分、隐含要求有没有漏掉”等拆成细粒度 rubric。

### 关键英文词

- **Fine-grained rubric**：细粒度评分标准。
- **Rubric compliance**：对评分要求的满足程度。
- **Factual grounding**：事实依据是否可靠。
- **Reasoning soundness**：推理是否站得住脚。
- **Implicit context**：用户没有逐字写出、但任务中隐含需要满足的条件。

### ASPR 怎么借

最终 Verifier 不要只给一个“review quality score”。

应使用 paper-specific rubric，逐项检查：

- novelty claim 是否被 prior art 支持；
- methodology criticism 是否有论文内证据；
- citation 是否真实、是否支持对应句子；
- graph signal 有没有被错误当成论文质量分；
- recommendation 是否与前面证据一致；
- reviewer 是否遗漏关键实验/局限。

**推荐度：★★★★☆。**

## 15. Failure is Feedback: History-Aware Backtracking for Agentic Traversal in Multimodal Graphs

**会议：ICML 2026**  
**文件：`17_Failure_is_Feedback_ICML2026_AuthorVersion.pdf`**

### 一句话先讲懂

第一次搜索失败不是应该丢掉的垃圾；“为什么没搜到”本身是下一次搜索最有价值的信息。

### 关键英文词

- **Backtracking**：回溯。发现当前路线走不通时退回之前节点重新走。
- **History-aware**：历史感知。下一次尝试会利用之前失败轨迹，而不是重新从零开始。
- **Dead end**：死路。继续沿当前搜索方向不会得到答案。
- **Cost-aware**：成本感知。只有失败确实值得时，才升级到更昂贵的模型/搜索方式。
- **Escalation**：升级处理。从便宜方案升级到昂贵但更强的方案。

### ASPR 怎么借

当 first/novel claim 第一轮没有找到 antecedent（前置先行工作）时，不要简单“换几个关键词再搜”。记录：

- 哪些 query 已经搜过；
- 命中了什么类型的无效论文；
- 缺的维度是什么（task/method/mechanism/domain/time）；
- 哪些旧术语可能没有覆盖。

第二轮 Counterfactual Search 读取这份 failure summary。

**推荐度：★★★★☆。**

## 16. CARD: Towards Conditional Design of Multi-agent Topological Structures

**会议：ICLR 2026**  
**文件：`13_CARD_ICLR2026_AuthorVersion.pdf`**

### 一句话先讲懂

Agent 的连接结构不应该永远固定；当模型、工具、知识源发生变化时，系统的工作路径也应该变化。

### 关键英文词

- **Conditional design**：条件化设计。根据当前条件产生不同结构。
- **Environmental signals**：环境信号，例如某工具不可用、模型升级、知识库变化。
- **Topology adaptation**：拓扑自适应。改变 Agent 的连接与执行顺序。
- **Runtime adaptation**：运行时自适应。不是训练好后固定，而是执行时还能改变。

### ASPR 怎么借

不要实现论文完整的条件图生成模型。只借条件路由：

- 没全文 → 不做强方法学结论；
- 没 graph packet → innovation 只用 prior-art/text evidence；
- 文献冲突 → 启动 citation/novelty specialist；
- 强统计贡献 → 启动 statistics specialist。

**推荐度：★★★☆☆。**

## 17. GraphPlanner: Graph Memory-Augmented Agentic Routing for Multi-Agent LLMs

**会议：ICLR 2026**  
**文件：`14_GraphPlanner_ICLR2026_AuthorVersion.pdf`**

### 一句话先讲懂

如果你手里有多个不同模型和角色，可以让 Router 根据当前任务和历史表现决定“这一步用哪个模型 + 哪个角色”。

### 关键英文词

- **Routing**：路由。决定当前任务交给谁。
- **Agentic routing**：智能体路由。不只是选模型，还选择角色和多步协作流程。
- **Heterogeneous graph memory**：异构图记忆。把 query、agent、response 等不同类型节点的历史交互存成图。
- **MDP (Markov Decision Process)**：马尔可夫决策过程。把“当前状态→选择动作→得到反馈→进入新状态”形式化。
- **Inductive inference**：归纳式泛化，对没见过的新任务也能工作。
- **Transductive inference**：利用当前已知任务/节点之间关系帮助预测。

### ASPR 怎么借

只有当 ASPR 以后真的同时维护：

`ASPR-Qwen + general LLM + statistics model + citation verifier + domain model`

才值得做 Model/Expert Router。当前阶段规则路由足够。

**推荐度：★★★☆☆。**

## 18. Multi-Agent Design: Optimizing Agents with Better Prompts and Topologies (MASS)

**会议：ICLR 2026**  
**文件：`15_MASS_ICLR2026.pdf`**

### 一句话先讲懂

多 Agent 系统的 prompt 和连接结构都可以自动搜索优化，而不是全靠开发者拍脑袋设计。

### 关键英文词

- **Prompt optimization**：提示词优化。
- **Topology optimization**：拓扑优化，自动寻找更好的 Agent 连接方式。
- **Block-level optimization**：局部模块级优化。
- **Workflow-level optimization**：整个工作流级优化。
- **Search space**：搜索空间，允许系统尝试的设计组合范围。

### ASPR 怎么借

只把 MASS 放在**离线开发阶段**。

例如在你的人工标注 review benchmark 上自动搜索：

- Evidence Supervisor 触发阈值；
- claim comparison prompt；
- verifier prompt；
- second-search 条件；
- Qwen / general LLM 的分工。

正式论文实验时冻结配置，保证可复现。

**推荐度：★★★☆☆。**

## 19. HieraMAS: Optimizing Intra-Node LLM Mixtures and Inter-Node Topology for Multi-Agent Systems

**会议：ICML 2026**  
**文件：`19_HieraMAS_ICML2026_AuthorVersion.pdf`**

### 一句话先讲懂

一个“功能节点”内部不一定只由一个 LLM 完成，可以让多个异构模型分别提出意见，再由一个合成器整合；同时节点之间的连接也可以优化。

### 关键英文词

- **Intra-node**：节点内部。
- **Inter-node**：节点之间。
- **Heterogeneous LLMs**：异构大模型，不同模型/大小/训练方式的 LLM。
- **Propose–synthesis**：先多个模型分别提出答案，再统一综合。
- **Supernode**：超级节点。一个逻辑功能节点内部其实由多个模型组成。
- **Reward attribution**：奖励归因。最终效果好坏应该算到哪个节点/模型身上。

### ASPR 怎么借

普通 claim 不需要。

只对非常高风险的强主张启用：

`first / breakthrough → two independent novelty judgments → synthesis`

也就是说，把它当作**高风险 claim 的双模型交叉确认机制**，而不是整个 ASPR 都做 HieraMAS。

**推荐度：★★★☆☆。**

# 最后：19 篇论文真正共同告诉 ASPR 什么

2026 年这些工作并不是在告诉你“应该增加更多 Agent”。相反，它们共同指向四个变化：

1. **角色中心 → 状态中心**：IterResearch、MEM1 强调维护紧凑、持续更新的工作状态。
2. **固定工作流 → 条件动作**：Eigen-Agent、SupervisorAgent、CARD 强调根据当前状态决定下一步。
3. **相似检索 → 关系/反事实检索**：SciNet、CF-RAG、FlowSearcher、FiF 强调检索本身也是推理过程。
4. **自报置信 → 过程校准**：Agentic Confidence、Epistemic Calibration 强调“系统是否真的有资格下结论”。

所以 ASPR 最值得做的不是再增加 Reviewer，而是把自己从“多个角色的对话系统”变成：

> **维护 Review State、主动补证据、按需调用能力、能够判断证据是否足以停止的科学评审智能体。**
