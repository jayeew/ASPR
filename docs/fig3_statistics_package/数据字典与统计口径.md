# 数据字典与统计口径

## 表格目录与粒度

| 表格 | 一行代表什么 | 主要用途 |
|---|---|---|
| overview.json | 整个实验概况 | 实际规模、已知token和缺失usage |
| paper_overview.csv | 一篇论文 | 领域、共享贡献/核心数、审稿问题数及适用问题数 |
| report_sizes.csv | 论文×方法 | 报告字符数、引用来源数，不含正文 |
| paper_metrics.csv | 论文×方法×指标 | 主指标明细，含分子分母、预期数及可估计值 |
| summary.csv | 方法×指标 | 论文宏平均、95%区间、微平均、总分子分母 |
| paired_differences.csv | Full减一个对照×指标 | 同论文配对差及区间，paper_ids为有效配对论文 |
| preference_pairs.csv | 论文×Full对照 | AB/BA结果、顺序敏感与是否两次均可判定 |
| costs.csv | 计算阶段×方法 | 全部已读取调用尝试的耗时与token汇总 |
| retrieval_costs.csv | 论文×外部基线 | 检索网络请求、来源获取及候选数量；此表仅覆盖代码导出的两个外部基线，不代表全部网络阶段 |
| recheck_coverage.csv | 论文×方法×复核类别 | 原计划、返回、可比较、相同、分歧、不可比较和缺少对象 |
| control_coverage.csv | 论文×控制类别 | 是否构造、计划/实际判断次数与状态 |
| *_counts.csv | 所列类别组合 | 全局记录计数；不是论文宏平均，也不是新的置信区间 |
| components/*.csv | 图组件统计行 | 与04相同的数值、类别、计数、分母和区间；仅32个无原文的组件表 |
| table_inventory.json | 一个统计文件 | 相对路径、行数及全部字段；无内容哈希 |

统计表中的paper_id允许关联相同论文，不能把方法/对象行视作独立论文样本。引用来源数是报告列出的来源数，不是经验证支持的来源数。`report_characters`为Python字符串长度，非token。

## 公共字段

- `method`：direct_a / eacl / reviewgrounder / gear / graph / fusion；fusion=Full。
- `metric`：具体指标，定义见下方及代码 `aggregate.py`。
- `value`：该论文指标；通常等于numerator/denominator。空值为不可估计，不是0。
- `numerator`、`denominator`：当前指标实际分子和分母。计数型指标通常以1作分母。
- `expected`：该计算步骤预期对象数量，未使用的指标可为空。
- `estimate`：在可估计论文上的宏平均；`low/high`为95%论文bootstrap区间。
- `n`：该行实际贡献数值的论文数；`missing`：所选论文中未贡献可估计数值的数量，不一定是程序失败。
- `micro`：合并分子/合并分母；与论文宏平均不是同一量。
- `primary`：Full−GEAR为主对比，其余是与另外四方法的对比。
- `count`：对应类别记录数；组件表的denominator是该方法/类别统计的对象总数。类别表的macro和micro不可混用。
- `same/different`：复核比较标签，不是正确/错误标签。`uncomparable`不进入一致率分母。

## 指标族

| 指标 | 含义与分母 |
|---|---|
| recall | 有效增量核心数 / 历史参考中positive核心数；缺少必要预测或评价时不估计 |
| precision | 有效增量核心数 / 在可评价核心上声明有增量的核心数 |
| historical_comparison | 适用核心中报告涉及且历史比较判断正确的比例 |
| scope_coverage | 适用核心中报告涉及且范围判断正确的比例 |
| false_firstness / false_antecedence / material_overclaim | 可用核心上对应布尔判断为true的比例，按现有04定义统计 |
| insufficient_material_assertions | 历史材料不足核心中的相关主张情况，精确条件见core_metrics |
| quality_* | 五维0—3分，逐维独立，不相加 |
| Mentioned / Substantive / Source_supported | 被报告提及、实质涉及或支持的共享贡献数 / 共享贡献总数 |
| S / T / S_minus_T | 支持且范围正确、其中原报告已给依据、两者差值 / 待核验断言数 |
| support_* | 待核验断言中对应支持状态的比例 |
| error_prevalence_* | 论文是否出现该错误（0/1），不是该错误断言比例 |
| errors_per100_* | 对应错误断言数×100 / 待核验断言数 |
| issue_coverage / reason_coverage | 覆盖适用审稿问题 / 适用问题；完整回应理由 / 有理由的适用问题 |
| information_count | 方法涉及的有效信息聚类数 |
| information_*（四类型） | 历史增量、跨文献关系、范围修正、跨贡献信息的聚类数 |
| information_density | 聚类数×1000 / 报告非空白字符数 |
| fusion_union/full/retained/not_retained/added | 分支并集、Full及交集/差集的聚类数 |
| important_retention | 保留的重要分支信息数 / 分支并集中重要信息数 |
| fusion_error_* / fusion_new_errors | 对应融合错误处理对象/新增错误数量 |
| preference_* | 顺序合并后的偏好指标，精确分值及不可判定处理见collect_preferences |
| *_technical_missing | 技术上缺失的对象计数，不能替代负面科学判断 |

这些是当前实现的描述，不新增阈值或重算定义。布尔空值表示未定，不宣称为false；具体指标是否要求全部对象完整、哪些对象适用，须结合分母和代码解释，不能仅凭列名扩展结论。

## 主要类别

R状态：supported_difference（有支持的差异）、bounded_increment（有限定的增量）、substantially_covered（基本已覆盖）、insufficient_material（材料不足）。

支持状态：supported、partly_supported、not_verifiable、contradicted。not_verifiable不是contradicted。

融合错误处理：explicitly_corrected、not_propagated、propagated、unknown。not_propagated不表示显式纠正。

控制类别：source_mismatch、firstness_overreach、scope_deletion。not_constructed表示候选范围内未构造该类配对，不能当作控制判断失败或认定整篇没有合适原句。

偏好：stable_full_win / stable_opponent_win / stable_tie、order_sensitive、cannot_judge及technical_failure；AB/BA均可判定的子集与全体配对的分母不同。

## 类别计数与重复记录

`verdicts_counts`按有效核心身份对齐：论文×方法×核心只计一次，采用与04相同的最后记录规则，忽略非核心ID；942个对象。其他 `*_counts` 直接描述对应最终导出表的类别记录数，不自动把一条记录解释为一条独立科学贡献。主结果优先使用paper_metrics与summary，而非从全局记录计数自行推导宏平均。

## 消耗口径

`calls`是日志可读的底层调用尝试数，包含失败、格式修复、材料阅读与补问，不是4500等顶层阶段任务数。`failures`为记录状态非completed的尝试计数；不意味着最终仍有相同数量未完成任务。`seconds`为每次调用耗时之和，因并发而不能当墙钟运行时间。

`input_tokens/output_tokens`只加总有usage的记录；`usage_missing`及`usage_complete`显示是否完整。完全未知时留空；部分未知时给出已知部分而非完整总量。overview中的known_*明确是已知累计值；5条不可读记录和192次无usage调用不能计为零消耗。输入token未拆缓存命中与未命中费用，本包不换算美元。不携带任何请求内容或错误日志。

## 重新计算

宏平均为每篇指标再求平均；微平均为合并分子/分母。paired_differences只使用双方均有数值的论文，以Full减对照。论文bootstrap共享抽样ID，重复10000次、种子20260922；它不是对象级独立抽样，区间也不是评委正确性保证。缺失/不适用不得用0填充。

代码中的展示清理只影响CSV/SVG不可显示字符，原始JSON保留原文。本包主动不携带含原文引文的JSON行级表，因此不能用于逐句证据审计；如需审计应回到原工作区。
