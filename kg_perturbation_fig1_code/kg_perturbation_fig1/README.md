# Fig. 1 real-data citation knowledge-graph perturbation pipeline

This project draws a real-data version of the Fig. 1 design:

- cumulative snapshots: 1-5, 1-10, 1-15, 1-20, 1-25 years;
- one fixed topic layout across snapshots;
- landmark papers marked as red stars;
- four perturbation signatures: Expansion, Bridging, Reconfiguration, Compression.

The default example is CRISPR-Cas genome editing. Other fields can be generated by changing only the YAML config.

## 1. Install

```bash
cd kg_perturbation_fig1
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 2. Get an OpenAlex API key

Create a free key at OpenAlex settings and export it:

```bash
export OPENALEX_API_KEY="YOUR_OPENALEX_KEY"
```

Optional:

```bash
export OPENALEX_EMAIL="your.email@example.com"
```

## 3. Run CRISPR

```bash
python fig1_knowledge_perturbation.py \
  --config configs/crispr.yaml \
  --out-dir results
```

Outputs will be saved under:

```text
results/crispr/
```

The main figure files are:

```text
fig1_crispr_real.png
fig1_crispr_real.svg
fig1_crispr_real.pdf
```

## 4. Run four fields for the full Fig. 1 layout

```bash
python fig1_knowledge_perturbation.py \
  --config configs/crispr.yaml configs/graphene.yaml configs/ipsc.yaml configs/transformer.yaml \
  --out-dir results_multi
```

The combined figure files are:

```text
results_multi/fig1_multi_domain_real.png
results_multi/fig1_multi_domain_real.svg
results_multi/fig1_multi_domain_real.pdf
```

## 5. Replace CRISPR with another field

Copy a YAML file and change only these fields:

```yaml
domain_name: "Your field"
slug: "your_field"
search_query: '("keyword 1" OR "keyword 2" OR "important phrase")'
start_year: 2000
end_year: 2024
anchors:
  - label: "Landmark author year"
    doi: "10.xxxx/xxxxx"
    year: 2012
```

Important knobs:

```yaml
max_works_per_window: 1200       # API download per rolling 5-year window
graph:
  max_papers_for_graph: 3500     # selected papers used for graph construction
  max_communities: 12            # number of displayed topic modules
plot:
  max_labels_per_panel: 8
```

## 6. Data tables

The script writes intermediate tables for reproducibility:

```text
works_raw.jsonl              # cached OpenAlex records after normalization
works_selected.csv           # papers actually used in graph construction
paper_edges.csv              # hybrid paper-level edges
topic_nodes.csv              # topic/community nodes in the displayed graph
topic_edges.csv              # topic/community edges
perturbation_metrics.csv     # raw and normalized four perturbation metrics
```

## 7. Metric definitions implemented in the script

### Expansion

New paper nodes, new graph edges and newly appearing primary topics in each rolling window.

### Bridging

Cross-community edge ratio, participation coefficient of new papers and top betweenness centrality of new papers.

### Reconfiguration

Community partition change between consecutive cumulative graphs, edge turnover and modularity shift.

### Compression

Shorter topic-level paths, increased hub concentration and reduced semantic dispersion of paper texts.

## 8. Practical notes

- Use `--no-cache` only when you really want to re-download data.
- For a first test, reduce `max_works_per_window` to 200 and `graph.max_papers_for_graph` to 800.
- For publication figures, increase them to 2000-5000 per window if API budget and compute time allow.
- For statistical claims, add matched controls and null models. This code is the Fig. 1 real-data visualization pipeline.
